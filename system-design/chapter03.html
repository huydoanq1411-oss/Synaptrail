Chương 3 — Load Balancing

Khi đã có nhiều server (Horizontal Scaling), cần một cơ chế phân phối request đều đặn giữa chúng.

Load Balancer đứng ở đâu?

                    ┌─────────────┐
Người dùng  ───────▶│Load Balancer│
                    └──────┬──────┘
                 ┌─────────┼─────────┐
                 ▼         ▼         ▼
            Server 1   Server 2   Server 3

Các thuật toán phân phối phổ biến

Thuật toánCách hoạt động
Round RobinPhân request lần lượt theo vòng tròn qua từng server
Least ConnectionsƯu tiên gửi tới server đang có ÍT kết nối đang xử lý nhất
IP HashBăm địa chỉ IP người dùng để LUÔN gửi về cùng 1 server (session affinity)
Quan trọng — Health Check
Load Balancer liên tục "kiểm tra sức khỏe" (health check) từng server — nếu một server ngừng phản hồi, Load Balancer TỰ ĐỘNG ngừng gửi request tới đó, chuyển hướng sang các server còn khỏe mạnh. Đây là cơ chế cốt lõi giúp hệ thống chịu lỗi (fault-tolerant).
Mẹo
Bản thân Load Balancer cũng có thể là "single point of failure" nếu chỉ có MỘT cái — hệ thống thực tế thường có ít nhất 2 Load Balancer (chính + dự phòng) để tránh toàn bộ hệ thống sập khi Load Balancer gặp sự cố.

📌 Tổng kết chương 3

Load Balancer phân phối request giữa nhiều server (Round Robin/Least Connections/IP Hash) và tự động loại bỏ server lỗi qua health check — thành phần bắt buộc khi áp dụng Horizontal Scaling.
