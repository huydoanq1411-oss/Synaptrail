API Gateway & Rate Limiting

Điểm vào duy nhất cho toàn bộ hệ thống microservices, và cơ chế bảo vệ hệ thống khỏi bị quá tải/lạm dụng.

API Gateway — "cổng" duy nhất vào hệ thống

Client ──▶ API Gateway ──┬──▶ Service Đăng nhập
                          ├──▶ Service Sản phẩm
                          ├──▶ Service Thanh toán
                          └──▶ Service Thông báo

Rate Limiting — giới hạn tốc độ request

y_tuong_rate_limiting.js 
// Thuật toán Token Bucket - ý tưởng phổ biến nhất
// Mỗi client có một "xô" chứa token, mỗi request tốn 1 token
// Token được "làm đầy" lại theo thời gian với tốc độ cố định

function kiemTraRateLimit(clientId) {
    const xo = layXoToken(clientId);
    if (xo.soToken > 0) {
        xo.soToken--;
        return true;       // cho phép request
    }
    return false;             // từ chối - trả về HTTP 429 Too Many Requests
}
Quan trọng
Rate Limiting bảo vệ hệ thống khỏi cả tấn công (DDoS) lẫn lỗi vô tình (một client bug gửi request lặp vô hạn) — không có rate limiting, một client duy nhất hành xử sai có thể làm sập toàn bộ hệ thống cho mọi người dùng khác.

📌 Tổng kết chương 9

API Gateway là điểm vào duy nhất, xử lý routing/xác thực/logging tập trung cho hệ thống microservices. Rate Limiting (VD: Token Bucket) giới hạn tốc độ request để bảo vệ hệ thống khỏi quá tải và lạm dụng.
