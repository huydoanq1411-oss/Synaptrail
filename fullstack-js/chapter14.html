Chương 14 — GraphQL — Query & Mutation

Ngôn ngữ truy vấn API thay thế REST — client tự quyết định CHÍNH XÁC dữ liệu nào cần lấy, không thừa không thiếu.

Vấn đề REST gặp phải: Over-fetching & Under-fetching

Vấn đềMô tả
Over-fetchingAPI REST trả về NHIỀU trường hơn client cần, lãng phí băng thông
Under-fetchingClient phải gọi NHIỀU endpoint khác nhau mới đủ dữ liệu cần hiển thị

GraphQL Query — chỉ lấy đúng field cần

query.graphql 
query {
  sanPham(id: 1) {
    ten                        # CHỈ lấy đúng những field liệt kê ở đây
    gia
    danhMuc {                    # lấy LUÔN dữ liệu quan hệ trong CÙNG 1 lần gọi
      ten
    }
  }
}

# Kết quả trả về CHÍNH XÁC những gì đã yêu cầu, không thừa field nào khác

Mutation — thay đổi dữ liệu (tương đương POST/PUT/DELETE)

mutation.graphql 
mutation {
  taoSanPham(ten: "Áo thun", gia: 150000) {
    id            # yêu cầu server trả về id vừa tạo
    ten
  }
}
Quan trọng
GraphQL chỉ có MỘT endpoint duy nhất (thường là /graphql), khác hẳn REST có nhiều endpoint riêng cho từng resource (/san-pham, /don-hang...). Loại truy vấn (Query để đọc, Mutation để ghi) được xác định qua NỘI DUNG gửi lên, không phải qua URL hay phương thức HTTP.

📌 Tổng kết chương 18

GraphQL Query cho phép client lấy CHÍNH XÁC dữ liệu cần (giải quyết over/under-fetching của REST), Mutation dùng để thay đổi dữ liệu — tất cả qua một endpoint duy nhất.
