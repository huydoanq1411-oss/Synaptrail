Chương 18 — NestJS — Dependency Injection & DTO

Hai khái niệm cốt lõi giúp code NestJS an toàn, dễ test và dễ bảo trì hơn hẳn cách viết Express thông thường.

Dependency Injection (DI) — NestJS tự động "tiêm" phụ thuộc

Ở chương 21, SanPhamController nhận SanPhamService qua constructor mà KHÔNG cần tự viết new SanPhamService() — NestJS tự động tạo và "tiêm" instance vào đúng chỗ cần dùng.

san-pham.module.ts 
import { Module } from '@nestjs/common';
import { SanPhamController } from './san-pham.controller';
import { SanPhamService } from './san-pham.service';

@Module({
    controllers: [SanPhamController],
    providers: [SanPhamService],          // khai báo Service này CÓ THỂ được tiêm cho controller trong module
})
export class SanPhamModule {}

DTO (Data Transfer Object) — xác thực dữ liệu đầu vào tự động

dto/tao-san-pham.dto.ts 
import { IsString, IsNumber, IsPositive, MinLength } from 'class-validator';

export class TaoSanPhamDto {
    @IsString()
    @MinLength(2)
    ten: string;

    @IsNumber()
    @IsPositive()                      // giá PHẢI là số dương
    gia: number;
}
san-pham.controller.ts 
@Post()
taoMoi(@Body() du_lieu: TaoSanPhamDto) {     // NestJS TỰ ĐỘNG kiểm tra du_lieu đúng DTO trước khi vào hàm
    return this.sanPhamService.taoMoi(du_lieu);
}
// Nếu client gửi "gia": -100 hoặc thiếu "ten" -> NestJS TỰ ĐỘNG trả lỗi 400, code KHÔNG CẦN tự viết if kiểm tra
Mẹo
DTO + class-validator loại bỏ hầu hết code kiểm tra if (!ten) return res.status(400)... lặp đi lặp lại mà bạn từng viết tay ở Express — validation trở thành khai báo (declarative), không phải logic thủ công.

📌 Tổng kết chương 22

Dependency Injection để NestJS tự quản lý vòng đời và "tiêm" các Service cần thiết. DTO kết hợp class-validator giúp xác thực dữ liệu đầu vào tự động, khai báo thay vì viết if thủ công.
