Chương 1 — Image, container và vòng đời cơ bản

Phân biệt gói môi trường với tiến trình đang chạy, rồi quan sát container tạo, chạy, dừng và được xóa.

1. Mục tiêu học

  • Giải thích vai trò image, container, client và Engine.
  • Chạy một container kiểm tra, đọc trạng thái và log.
  • Phân biệt dừng container, xóa container và xóa image.

Phần thực hành dùng Linux container và Docker CLI. Máy cần Docker Engine hoặc Docker Desktop hoạt động; trên Desktop hãy chọn môi trường Linux containers. Bài không tự cài Docker, thay cấu hình hệ thống hoặc chạy ứng dụng production. Lần lấy image đầu tiên cần mạng và quyền truy cập registry.

2. Vấn đề thực tế

Một nhóm chạy cùng ứng dụng nhưng mỗi máy có phiên bản công cụ khác nhau. Người mới thường mất thời gian tái tạo môi trường trước khi sửa được mã. Container giúp đóng gói và chạy những thành phần trong môi trường rõ hơn, nhưng bạn vẫn phải hiểu cấu hình nào nằm trong image và trạng thái nào phát sinh khi chạy.

Chương này không bắt đầu bằng Dockerfile phức tạp hay ba dịch vụ Compose. Thay vào đó, dùng một chương trình ngắn chạy xong rồi thoát để thấy container không phải “một máy tính luôn bật”. Khi hiểu vòng đời, việc tìm lỗi dịch vụ ở chương sau sẽ ít dựa vào phỏng đoán hơn.

3. Lý thuyết nền

Image là gói file, thành phần và cấu hình để tạo container. Một image có thể tạo nhiều container. Container là một phiên chạy với tiến trình và trạng thái riêng; dừng hoặc xóa một container không tự xóa image đã dùng để tạo nó.

Docker CLI gửi yêu cầu tới Engine. Vì vậy có executable docker trong PATH chưa chứng minh server đã sẵn sàng. Image cũng cần phù hợp nền tảng của runtime; “có image” không bảo đảm nó chạy trên mọi kiến trúc mà không điều kiện.

Linux container dựa vào kernel của môi trường chạy, không phải mỗi container có một kernel riêng như máy ảo đầy đủ. Docker Desktop có thể cung cấp môi trường Linux qua máy ảo. Không nên hiểu sự cô lập container là lý do bỏ qua quyền, secrets hoặc bảo mật; những vấn đề này được học riêng trong chương 8.

4. Ví dụ từng bước

Đầu tiên kiểm tra client và server. Nếu lỗi kết nối Engine, dừng thực hành tại đây và khởi động môi trường Docker theo hướng dẫn cài đặt của bạn. Không đổi quyền toàn hệ thống chỉ vì một lệnh kiểm tra không kết nối được.

Terminal — kiểm tra và lấy image
docker version
docker pull hello-world:latest
docker image ls hello-world
  1. version cho biết thông tin client/server; chỉ có phần client thì cần kiểm tra Engine.
  2. pull lấy image hello-world từ registry mặc định nếu có quyền và kết nối mạng.
  3. image ls lọc danh sách để bạn thấy image có trên máy. Nó chưa tạo container.

Tag latest ở đây chỉ dùng cho bài kiểm tra ngắn, không phải khóa phiên bản bất biến. Với dự án cần tái lập, khóa phiên bản hoặc digest được học ở chương image. Bài không dùng kết quả Hello World để tuyên bố môi trường production đã an toàn.

Terminal — tạo, quan sát và dọn container bài tập
docker run --name synaptrail-docker-intro hello-world:latest
docker ps -a --filter name=synaptrail-docker-intro
docker logs synaptrail-docker-intro
docker rm synaptrail-docker-intro
  1. run tạo container mới với tên cụ thể, rồi chạy chương trình của image. Nếu tên đã tồn tại, không chạy lại ngay: kiểm tra container bài tập cũ trước.
  2. Chương trình Hello World in thông báo và kết thúc. Trạng thái Exited với mã 0 là kết quả thành công dự kiến, không phải lỗi chỉ vì nó không còn running.
  3. ps -a liệt kê cả container đã dừng; bộ lọc giới hạn việc quan sát vào tên bài tập.
  4. logs đọc thông báo đầu ra của container đã tạo, giúp kiểm tra chương trình thực sự chạy.
  5. rm xóa đúng container bài tập đã thoát. Lệnh này không yêu cầu xóa image; image vẫn có thể tạo container mới.

Không dùng --rm ở bước đầu vì cần giữ container đã thoát để xem trạng thái và log. Khi đã quan sát xong, mới dọn theo tên. Bài không cần publish port, mount dữ liệu hay chạy đặc quyền; thêm các tùy chọn này sớm chỉ làm bạn khó phân biệt tác dụng từng lệnh.

Trong vòng đời thông thường, docker stop yêu cầu một container đang chạy dừng lại. Nó khác rm, vốn xóa container. Ví dụ Hello World tự kết thúc, nên không cần gọi stop cho nó. Khi làm dịch vụ chạy lâu ở chương sau, bạn sẽ luyện rõ hơn bước start/stop.

5. Lỗi thường gặp

  • Nhầm docker ps không có -a là danh sách tất cả: container đã thoát sẽ không xuất hiện ở danh sách đang chạy.
  • Tưởng sửa hoặc xóa container sẽ cập nhật image gốc: image và phiên chạy là hai đối tượng khác nhau.
  • Chạy lại run cùng tên rồi nhận lỗi: kiểm tra container bài tập tồn tại; đừng xóa các container không thuộc bài.
  • Thấy Exited liền kết luận lỗi: đọc exit code và logs để phân biệt chương trình hoàn tất với chạy thất bại.
  • Cho rằng container tự bảo đảm an toàn: quyền và cách cấu hình vẫn là trách nhiệm cần kiểm tra.

6. Bài tập ba mức

Dễ

Chỉ rõ lệnh nào lấy image và lệnh nào tạo container. Ghi lại tên container và trạng thái quan sát được, không sao chép ID minh họa từ tài liệu.

Vừa

Tạo hai container kiểm tra với hai tên riêng từ cùng image, quan sát ps -a và logs. Dọn đúng hai container bài tập; kiểm tra image vẫn có trên máy.

Khó

Viết checklist chẩn đoán khi run không có kết quả mong muốn: client/server, image, tên trùng, trạng thái, exit code và log. Phân biệt việc đọc thông tin với thao tác xóa; không dùng lệnh dọn toàn hệ thống.

7. Tóm tắt

Image dùng để tạo container; container sống theo tiến trình của nó. Có CLI chưa đủ nếu Engine chưa chạy. Quan sát bằng ps/logs trước khi dọn. Dừng, xóa container và xóa image là những thao tác khác nhau.
