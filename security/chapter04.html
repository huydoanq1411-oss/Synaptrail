CSRF (Cross-Site Request Forgery)

Lừa trình duyệt của nạn nhân (đã đăng nhập) tự động gửi request thực hiện hành động mà họ không hề biết.

Làm quiz ở trang riêng

Lừa trình duyệt của nạn nhân (đã đăng nhập) tự động gửi request thực hiện hành động mà họ không hề biết.

Cách kẻ tấn công khai thác

1. Nạn nhân ĐÃ đăng nhập vào ngan-hang.com (cookie phiên đăng nhập còn hiệu lực)
2. Nạn nhân bị dụ mở một trang web ĐỘC HẠI (VD: qua email lừa đảo)
3. Trang độc hại chứa:
   <img src="https://ngan-hang.com/chuyen-tien?toi=hacker&so_tien=1000000">
4. Trình duyệt TỰ ĐỘNG gửi request này, KÈM THEO cookie đăng nhập ngân hàng
   (vì cookie được gửi tự động cho MỌI request tới đúng domain đó)
5. Ngân hàng thấy request có cookie hợp lệ -> TIN TƯỞNG -> thực hiện chuyển tiền!

Cách phòng chống: CSRF Token

phong_chong_csrf.js 
// Server sinh một token NGẪU NHIÊN, duy nhất cho mỗi phiên/form
app.get('/form-chuyen-tien', (req, res) => {
    const csrfToken = sinhTokenNgauNhien();
    req.session.csrfToken = csrfToken;
    res.render('form', { csrfToken });
});

app.post('/chuyen-tien', (req, res) => {
    if (req.body.csrfToken !== req.session.csrfToken) {
        return res.status(403).send('CSRF token không hợp lệ');
    }
    // token khớp -> request THẬT SỰ đến từ form của chính trang web, không phải giả mạo
});
Mẹo
Kẻ tấn công CSRF KHÔNG THỂ đọc được nội dung trang ngan-hang.com (đó là XSS, vấn đề khác) — CSRF chỉ lợi dụng việc trình duyệt tự động gửi cookie, KHÔNG biết token bí mật đã sinh ra cho form thật. Đây là lý do CSRF token hiệu quả: kẻ tấn công không có cách nào lấy được token đúng để giả mạo request.

📌 Tổng kết chương 4

CSRF lợi dụng việc trình duyệt tự động gửi cookie để giả mạo hành động của người dùng đã đăng nhập. CSRF Token (giá trị bí mật kẻ tấn công không biết) là cách phòng chống chuẩn.
