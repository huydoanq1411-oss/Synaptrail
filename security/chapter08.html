Chương 8 — Phân quyền (Authorization) & Least Privilege

Xác thực (Authentication) trả lời "bạn là ai?" — Phân quyền (Authorization) trả lời "bạn ĐƯỢC PHÉP làm gì?". Hai khái niệm hay bị nhầm lẫn nhưng hoàn toàn khác nhau.

Role-Based Access Control (RBAC)

rbac_middleware.js 
function phanQuyen(...vaiTroChoPhep) {           // middleware nhận danh sách vai trò được phép
    return (req, res, next) => {
        if (!vaiTroChoPhep.includes(req.user.vaiTro)) {
            return res.status(403).json({ loi: 'Bạn không có quyền thực hiện thao tác này' });
        }
        next();
    };
}

// Chỉ admin mới được xóa sản phẩm
app.delete('/san-pham/:id', xacThuc, phanQuyen('admin'), (req, res) => {
    // ... logic xóa sản phẩm
});

// Cả admin lẫn nhân viên bán hàng đều xem được đơn hàng
app.get('/don-hang', xacThuc, phanQuyen('admin', 'nhan_vien'), (req, res) => {
    // ...
});
Quan trọng — Lỗ hổng IDOR
IDOR (Insecure Direct Object Reference) — lỗi cực kỳ phổ biến: chỉ kiểm tra "đã đăng nhập chưa" mà QUÊN kiểm tra "có phải chủ sở hữu dữ liệu này không". VD: GET /don-hang/123 — nếu không kiểm tra đơn hàng 123 có thuộc về user đang đăng nhập hay không, bất kỳ ai đăng nhập cũng có thể xem đơn hàng của NGƯỜI KHÁC chỉ bằng cách đổi số ID trên URL.
phong_chong_idor.js 
app.get('/don-hang/:id', xacThuc, async (req, res) => {
    const donHang = await DonHang.findByPk(req.params.id);
    if (!donHang) return res.status(404).json({ loi: 'Không tìm thấy' });

    // KIỂM TRA QUYỀN SỞ HỮU - bước hay bị bỏ quên nhất
    if (donHang.userId !== req.user.id && req.user.vaiTro !== 'admin') {
        return res.status(403).json({ loi: 'Bạn không có quyền xem đơn hàng này' });
    }
    res.json(donHang);
});
Mẹo — Least Privilege
Nguyên tắc "Đặc quyền tối thiểu": mỗi user/service chỉ nên có ĐÚNG quyền cần thiết cho công việc của họ, không hơn. Một nhân viên hỗ trợ khách hàng không cần quyền XÓA database — dù họ hoàn toàn "đáng tin cậy", giới hạn quyền giúp giảm thiệt hại nếu tài khoản đó bị chiếm đoạt.

1. Lỗ hổng IDOR xảy ra khi nào?

Khi mật khẩu không được hash Khi hệ thống chỉ kiểm tra đăng nhập mà quên kiểm tra quyền sở hữu dữ liệu Khi không dùng HTTPS

📌 Tổng kết chương 8

Authorization (được phép làm gì) khác Authentication (là ai). RBAC gán quyền theo vai trò; luôn kiểm tra quyền SỞ HỮU dữ liệu cụ thể để tránh lỗ hổng IDOR — một trong những lỗi phổ biến và nguy hiểm nhất trong thực tế.
