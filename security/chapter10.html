Tổng hợp toàn bộ kiến thức thành danh sách kiểm tra thực tế — áp dụng trước khi đưa bất kỳ ứng dụng nào lên production.

Checklist tổng hợp

  • ✅ Input Validation (ch.9): Mọi input từ client đều validate ở SERVER, không chỉ client
  • ✅ SQL Injection (ch.2): Dùng prepared statement/ORM, không nối chuỗi SQL trực tiếp
  • ✅ XSS (ch.3): Không dùng dangerouslySetInnerHTML/innerHTML với dữ liệu chưa lọc
  • ✅ CSRF (ch.4): Có CSRF token cho các thao tác thay đổi dữ liệu quan trọng
  • ✅ Mật khẩu (ch.5): Hash bằng bcrypt, không lưu dạng gốc hay mã hóa 2 chiều
  • ✅ Token/Session (ch.6): JWT_SECRET đủ mạnh, thời gian hết hạn hợp lý
  • ✅ HTTPS (ch.7): Toàn bộ traffic qua HTTPS, không có endpoint HTTP thuần
  • ✅ Authorization/IDOR (ch.8): Kiểm tra quyền sở hữu dữ liệu, không chỉ kiểm tra đăng nhập
  • ✅ Secrets (ch.9): Không có API key/mật khẩu nào hardcode trong code hoặc commit lên Git
  • ✅ Rate Limiting (ch.9): Giới hạn request cho các endpoint nhạy cảm (đăng nhập, đăng ký)
  • ✅ Dependency: Cập nhật thư viện thường xuyên (npm audit) — lỗ hổng thường nằm ở thư viện bên thứ ba lỗi thời
  • ✅ Error Message: Thông báo lỗi cho người dùng KHÔNG tiết lộ chi tiết kỹ thuật (stack trace, cấu trúc database)
Cảnh báo — Error Message rò rỉ thông tin
Trả về lỗi database thô (VD: "Column 'password' does not exist in table 'users'") cho client vô tình tiết lộ cấu trúc database cho kẻ tấn công. Luôn trả về thông báo lỗi CHUNG CHUNG cho người dùng, ghi log chi tiết ở phía SERVER để debug riêng.
Mẹo — Tư duy cuối cùng
Bảo mật không phải đích đến mà là quá trình liên tục — không hệ thống nào "bảo mật tuyệt đối". Mục tiêu thực tế là làm cho việc tấn công TỐN KÉM và KHÓ KHĂN hơn giá trị mà kẻ tấn công có thể thu được, đồng thời có khả năng PHÁT HIỆN và PHẢN ỨNG nhanh khi sự cố xảy ra.
