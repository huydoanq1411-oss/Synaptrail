HTTPS/TLS & Mã hóa dữ liệu

Bảo vệ dữ liệu khi đang di chuyển trên mạng — ngăn kẻ tấn công "nghe lén" giữa client và server.

HTTP vs HTTPS

HTTP gửi dữ liệu dạng văn bản thô (plain text) — bất kỳ ai kiểm soát mạng trung gian (wifi công cộng, ISP...) đều có thể đọc được nội dung, kể cả mật khẩu. HTTPS = HTTP + TLS (Transport Layer Security), mã hóa toàn bộ dữ liệu trao đổi.

Bắt tay TLS (TLS Handshake) — sơ lược

1. Client kết nối tới server, yêu cầu bắt tay HTTPS
2. Server gửi CHỨNG CHỈ SSL (SSL Certificate) chứa public key
3. Client kiểm tra chứng chỉ có được CA (Certificate Authority) tin cậy ký không
4. Client và server thống nhất một khóa bí mật CHUNG (session key)
   thông qua mã hóa bất đối xứng (asymmetric encryption)
5. Từ đây, toàn bộ dữ liệu được mã hóa bằng khóa chung đó
   (mã hóa đối xứng - symmetric encryption, nhanh hơn nhiều)

Mẹo
Let's Encrypt (đã nhắc ở giáo trình Full-Stack JS chương 25) cung cấp chứng chỉ SSL MIỄN PHÍ và tự động gia hạn — không còn lý do gì để một trang web hiện đại chạy HTTP thuần thay vì HTTPS.
Quan trọng
HTTPS bảo vệ dữ liệu ĐANG DI CHUYỂN (in transit) — KHÔNG bảo vệ dữ liệu đã lưu trong database (at rest). Mật khẩu vẫn phải hash (chương 5) dù đã có HTTPS; hai lớp bảo vệ này độc lập và đều cần thiết.

📌 Tổng kết chương 7

HTTPS = HTTP + TLS, mã hóa dữ liệu trên đường truyền qua bắt tay TLS (kết hợp mã hóa bất đối xứng để trao đổi khóa, rồi mã hóa đối xứng cho dữ liệu thực tế). Bảo vệ dữ liệu "đang di chuyển", khác với hash mật khẩu bảo vệ dữ liệu "đã lưu trữ".
