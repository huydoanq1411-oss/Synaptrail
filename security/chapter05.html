Hashing mật khẩu với bcrypt

terminal 
npm install bcrypt
auth.js 
const bcrypt = require('bcrypt');

async function dangKy(matKhau) {
    const soVongLap = 12;                          // càng cao càng an toàn nhưng càng chậm
    const matKhauDaHash = await bcrypt.hash(matKhau, soVongLap);
    // LƯU matKhauDaHash vào database - KHÔNG BAO GIỜ lưu matKhau gốc
    return matKhauDaHash;
}

async function dangNhap(matKhauNhap, matKhauDaHashTrongDB) {
    const khop = await bcrypt.compare(matKhauNhap, matKhauDaHashTrongDB);
    return khop;   // true/false - so sánh AN TOÀN, không cần "giải mã" ngược lại
}
Quan trọng — Hashing khác Encryption
Hashing (bcrypt) là quá trình MỘT CHIỀU — không thể "giải mã" ngược lại thành mật khẩu gốc, chỉ có thể SO SÁNH. Encryption (mã hóa) là HAI CHIỀU — có thể giải mã ngược nếu có khóa. Mật khẩu LUÔN dùng hashing, không bao giờ dùng encryption thông thường.

Tại sao không tự viết hàm hash, hay dùng MD5/SHA1?

Vấn đềGiải thích
MD5/SHA1 quá nhanhKẻ tấn công có thể thử hàng tỷ mật khẩu/giây (brute-force) để tìm ra khớp hash
bcrypt CỐ TÌNH chậmCó tham số "cost factor" (số vòng lặp) điều chỉnh được, làm brute-force trở nên bất khả thi về mặt thời gian
bcrypt tự động "salt"Mỗi hash có một chuỗi ngẫu nhiên riêng trộn vào, chống lại "rainbow table" (bảng tra cứu hash có sẵn)

📌 Tổng kết chương 5

Mật khẩu luôn lưu dưới dạng hash (bcrypt), không bao giờ dạng gốc hay mã hóa hai chiều. bcrypt cố tình chậm và tự động salt để chống brute-force và rainbow table — không nên tự viết hàm hash hay dùng MD5/SHA1 cho mật khẩu.

Ghi chú — Argon2
bcrypt vẫn hoàn toàn an toàn và được dùng rộng rãi, nhưng khuyến nghị hiện hành của OWASP xếp Argon2id là lựa chọn ưu tiên số một cho hệ thống mới (nhà vô địch cuộc thi Password Hashing Competition) — vì có thể điều chỉnh cả chi phí CPU LẪN bộ nhớ (RAM) cần thiết để tính hash, chống lại được cả kiểu tấn công dùng phần cứng chuyên dụng (GPU/ASIC) hiệu quả hơn bcrypt. bcrypt vẫn là lựa chọn ổn khi hệ thống/thư viện chưa hỗ trợ Argon2.
