Hai cách phổ biến nhất để "nhớ" người dùng đã đăng nhập giữa các request — mỗi cách có đánh đổi bảo mật riêng.

Session-based Authentication (truyền thống)

1. Đăng nhập thành công -> Server tạo session, lưu trong database/memory
2. Server gửi session ID cho client qua cookie
3. Mỗi request sau đó, client gửi kèm cookie -> server TRA CỨU session trong database

JWT (JSON Web Token) — không cần lưu ở server

jwt_auth.js 
const jwt = require('jsonwebtoken');

// Đăng nhập - tạo token
function taoToken(user) {
    return jwt.sign(
        { id: user.id, email: user.email },     // payload - dữ liệu nhúng trong token
        process.env.JWT_SECRET,                     // khóa bí mật - PHẢI giữ kín tuyệt đối
        { expiresIn: '1h' }                            // token tự hết hạn sau 1 giờ
    );
}

// Middleware kiểm tra token ở mọi request cần bảo vệ
function xacThuc(req, res, next) {
    const token = req.headers.authorization?.split(' ')[1];
    try {
        req.user = jwt.verify(token, process.env.JWT_SECRET);   // giải mã VÀ kiểm tra chữ ký
        next();
    } catch (err) {
        res.status(401).json({ loi: 'Token không hợp lệ hoặc đã hết hạn' });
    }
}

Cảnh báo
JWT_SECRET bị lộ = kẻ tấn công có thể TỰ TẠO token giả mạo bất kỳ ai, kể cả admin. Luôn lưu trong biến môi trường, không commit lên Git (đã học ở Full-Stack JS chương 2 — file .gitignore).

📌 Tổng kết chương 6

Session lưu trạng thái ở server, dễ thu hồi nhưng cần tra cứu database mỗi request. JWT tự chứa thông tin, không cần lưu server nhưng khó thu hồi trước hạn — lựa chọn tùy kiến trúc (monolith vs microservices/SPA).
