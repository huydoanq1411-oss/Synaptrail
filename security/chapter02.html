Chương 2 — SQL Injection

Lỗ hổng kinh điển nhất — đã nhắc tới ở giáo trình Full-Stack JS, giờ đào sâu cách khai thác và phòng chống toàn diện.

Cách kẻ tấn công khai thác

code_de_bi_tan_cong.js 
// NGUY HIỂM - nối chuỗi trực tiếp từ input người dùng
const query = `SELECT * FROM users WHERE username='${username}' AND password='${password}'`;

// Kẻ tấn công nhập vào ô username:
//   admin' --
// Câu SQL thực tế trở thành:
//   SELECT * FROM users WHERE username='admin' --' AND password='...'
// Dấu -- biến phần sau thành COMMENT, bỏ qua hoàn toàn việc kiểm tra password!
// -> Đăng nhập được vào tài khoản admin mà KHÔNG CẦN biết mật khẩu

Cách phòng chống: Prepared Statement

code_an_toan.js 
// AN TOÀN - dùng dấu ? (đã học ở Full-Stack JS chương 15)
const [rows] = await pool.query(
    'SELECT * FROM users WHERE username = ? AND password = ?',
    [username, password]
);
// Thư viện tự động "escape" dữ liệu - input dù có chứa ký tự đặc biệt
// cũng CHỈ được hiểu là DỮ LIỆU, không bao giờ được hiểu là CÂU LỆNH SQL
Mẹo
Dùng ORM (Sequelize/Prisma đã học) hoặc query builder gần như tự động miễn nhiễm SQL Injection vì chúng luôn dùng prepared statement bên dưới — đây là một lý do thực tế nữa (ngoài sự tiện lợi) để ưu tiên ORM thay vì tự nối chuỗi SQL.

📌 Tổng kết chương 2

SQL Injection khai thác việc nối chuỗi SQL trực tiếp từ input người dùng. Phòng chống bằng prepared statement (dấu ?) hoặc ORM — không bao giờ tự nối chuỗi để tạo câu lệnh SQL.
