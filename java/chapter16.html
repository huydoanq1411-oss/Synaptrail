ArrayList & LinkedList

Chọn ArrayList hoặc LinkedList theo thao tác, phân biệt xóa theo chỉ số/giá trị và dùng Iterator an toàn.

Làm quiz ở trang riêng

Quản lý một danh sách có thứ tự, chọn cấu trúc theo thao tác thực tế và tránh xóa nhầm phần tử khi dùng List<Integer>.

Mục tiêu

  • Dùng List để thêm, đọc, sửa, xóa và duyệt dữ liệu.
  • Phân biệt ArrayList với LinkedList theo chi phí thao tác.
  • Hiểu hai overload (phiên bản cùng tên) của remove và xóa an toàn qua Iterator.

Vấn đề thực tế

Bạn lưu các bài cần học theo thứ tự: Java, SQL, Java. Hai lần Java là hai lượt ôn khác nhau nên không được tự loại trùng. Bạn cần xem bài đầu, đổi tên một mục và xóa đúng lượt đã hoàn thành. Mảng có kích thước cố định; List cung cấp thao tác thay đổi số phần tử phù hợp hơn cho trường hợp này.

Lý thuyết nền

List là hợp đồng, ArrayList và LinkedList là cách cài đặt

List là interface (giao diện) cho danh sách có thứ tự; chỉ số bắt đầu từ 0. Hai cài đặt trong bài cho phép phần tử trùng và null. Khai báo List<String> giúp đoạn xử lý chỉ phụ thuộc thao tác cần dùng. Khi cần thao tác hai đầu, Deque (hàng đợi hai đầu) diễn đạt mục đích rõ hơn; không phải mọi biến đều bắt buộc có kiểu List.

Chi phí theo n phần tử; không phải số đo tốc độ thực tế

Tìm hoặc xóa theo giá trịO(n) trường hợp xấu nhấtO(n) trường hợp xấu nhất

Khấu hao nghĩa là xét tổng chi phí của nhiều lần thêm: một lần có thể đắt nhưng trung bình trên chuỗi thao tác vẫn có cận hằng số. size là số phần tử đang có; capacity là số chỗ mảng nền có thể chứa. Tăng capacity không tạo thêm phần tử để get.

Đừng kết luận “LinkedList chèn/xóa luôn nhanh”: tìm vị trí vẫn mất thời gian. Duyệt LinkedList bằng get(i) trong vòng lặp chỉ số có thể O(n²); enhanced for (vòng lặp for-each) hoặc Iterator duyệt một lượt O(n). LinkedList còn có chi phí lưu các liên kết. Hãy bắt đầu bằng ArrayList cho danh sách thường đọc/duyệt, sau đó chọn lại theo thao tác và phép đo của bài toán; bảng Big O không thay benchmark.

Ví dụ có thể chạy và giải thích

Hai chương trình độc lập dùng Java 8 trở lên, không thư viện ngoài. Cần JDK có javac; JRE chỉ chạy chương trình đã biên dịch. Lưu đúng tên tệp ghi trên mỗi khối, chạy javac -encoding UTF-8 ListDemo.java rồi java ListDemo; ví dụ thứ hai thay tên bằng ListRemovalDemo. Các dòng output dự kiến được chú thích ngay sau lệnh in.

ListDemo.java
import java.util.ArrayList;
import java.util.Deque;
import java.util.LinkedList;
import java.util.List;

public class ListDemo {
    public static void main(String[] args) {
        List<String> lessons = new ArrayList<>();
        lessons.add("Java");
        lessons.add("SQL");
        lessons.add("Java");
        lessons.set(1, "HTML");
        System.out.println(lessons.get(0)); // Java
        System.out.println(lessons);        // [Java, HTML, Java]
        lessons.remove("Java");
        System.out.println(lessons);        // [HTML, Java]
        for (String lesson : lessons) {
            System.out.println(lesson);     // HTML, roi Java tren dong rieng
        }
        Deque<String> review = new LinkedList<>();
        System.out.println(review.pollFirst()); // null: dang rong
        review.addLast("Java");
        review.addFirst("SQL");
        System.out.println(review.pollFirst()); // SQL
        System.out.println(review);             // [Java]
    }
}
  1. Các import chỉ rõ kiểu dùng từ java.util. main là điểm vào khi chạy java ListDemo.
  2. new ArrayList<>() tạo danh sách rỗng. Ba lần add giữ cả hai mục Java và thứ tự thêm.
  3. set(1, "HTML") thay SQL, không tăng size. get(0) đọc mục đầu; chỉ số đọc/sửa hợp lệ là 0 đến size() - 1.
  4. remove("Java") chọn overload nhận đối tượng, chỉ bỏ lần xuất hiện đầu. Vòng for-each đọc hai mục còn lại.
  5. Deque khai báo nhu cầu thao tác hai đầu. pollFirst trả null nếu rỗng; addLast thêm cuối và addFirst thêm đầu. Ví dụ không lưu null để có thể dùng null làm dấu hiệu rỗng.

Phân biệt xóa theo chỉ số với xóa theo giá trị

ListRemovalDemo.java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Iterator;
import java.util.List;

public class ListRemovalDemo {
    public static void main(String[] args) {
        List<Integer> scores = new ArrayList<>(Arrays.asList(10, 20, 10));
        int removed = scores.remove(1);
        System.out.println(removed); // 20: xoa theo chi so
        boolean found = scores.remove(Integer.valueOf(10));
        System.out.println(found);   // true: xoa gia tri 10 dau tien
        System.out.println(scores);  // [10]
        System.out.println(scores.remove(Integer.valueOf(99))); // false
        scores.add(3);
        scores.add(4);
        Iterator<Integer> it = scores.iterator();
        while (it.hasNext()) {
            int score = it.next();
            if (score < 5) {
                it.remove();
            }
        }
        System.out.println(scores); // [10]
        scores.clear();
        System.out.println(scores.isEmpty()); // true
    }
}
  1. Arrays.asList tạo danh sách kích thước cố định; bọc bằng new ArrayList để có bản sao cho phép thêm/xóa.
  2. Đối số 1 có kiểu int nên remove(1) xóa phần tử ở chỉ số 1 và trả giá trị 20. Trên List<Integer>, remove(10) cũng là xóa chỉ số 10, không phải tìm số 10.
  3. Integer.valueOf(10) tạo đối số kiểu Integer để chọn remove(Object). Phương thức trả boolean; giá trị không tồn tại trả false.
  4. Iterator là đối tượng duyệt. hasNext kiểm tra còn phần tử, next lấy phần tử và tiến vị trí; remove bỏ đúng phần tử vừa lấy.
  5. Chỉ gọi it.remove một lần sau mỗi next. Không gọi scores.remove trong lúc iterator đang duyệt. clear xóa tất cả; isEmpty kiểm tra danh sách rỗng.

Lỗi thường gặp

  • get(size()) gây IndexOutOfBoundsException. Với danh sách rỗng, không có chỉ số đọc hợp lệ; kiểm isEmpty trước khi đọc đầu.
  • Nhầm size với capacity: new ArrayList<String>(100) vẫn có size bằng 0.
  • Xóa trực tiếp khỏi danh sách trong for-each có thể làm iterator phát hiện thay đổi cấu trúc và ném ConcurrentModificationException. Đừng dựa vào việc một lần thử chưa ném lỗi; dùng iterator.remove đúng quy tắc như ví dụ.
  • Gọi it.remove trước next hoặc hai lần sau cùng một next gây IllegalStateException với iterator trong bài.
  • Hai cấu trúc này không tự đồng bộ khi nhiều thread cùng sửa. Bài này chỉ dùng một thread; xem phần concurrency trước khi chia sẻ danh sách giữa các thread.

Bài tập ba mức

  1. Cơ bản: tạo danh sách rỗng, thêm Java, SQL, Java; sửa SQL thành HTML, xóa một Java theo giá trị. Tự kiểm: còn [HTML, Java], size bằng 2.
  2. Vận dụng: với [10, 20, 10], chạy hai chương trình riêng: một xóa chỉ số 1; một xóa giá trị 10. Tự kiểm: lần lượt [10, 10] và [20, 10]. Thử tiếp giá trị 99 không tồn tại và danh sách rỗng; không gọi remove(int) khi chỉ số không hợp lệ.
  3. Nâng cao: viết hàm xóa mọi điểm dưới 5 bằng Iterator; chạy cùng logic trên ArrayList và LinkedList. Ca tự kiểm: [] thành [], [3] thành [], [5, 7] giữ nguyên, [2, 2, 6, 1] thành [6]. Giải thích vì sao dùng iterator thay cho get(i) khi duyệt LinkedList.

Tóm tắt

List giữ thứ tự và cho phép phần tử trùng trong các cài đặt đã học. ArrayList thuận tiện cho đọc theo chỉ số; LinkedList cung cấp thao tác đầu/cuối nhưng truy cập vị trí giữa vẫn cần duyệt. Chọn remove(int) hoặc remove(Object) có chủ đích, và dùng iterator.remove để xóa trong khi duyệt.
