ExecutorService

Cách quản lý thread hiện đại, chuyên nghiệp hơn việc tự tạo Thread thủ công — dùng "thread pool".

Cách quản lý thread hiện đại, chuyên nghiệp hơn việc tự tạo Thread thủ công — dùng "thread pool".

ExecutorServiceDemo.java 
import java.util.concurrent.*;

public class Main {
    public static void main(String[] args) throws Exception {
        ExecutorService executor = Executors.newFixedThreadPool(3);    // pool gồm 3 luồng tái sử dụng

        for (int i = 1; i <= 5; i++) {
            int taskId = i;
            executor.submit(() -> {
                System.out.println("Đang xử lý task " + taskId + " bởi " + Thread.currentThread().getName());
            });
        }

        executor.shutdown();                                    // không nhận task mới, chờ task hiện tại xong

        // Future - lấy kết quả trả về từ task bất đồng bộ
        ExecutorService executor2 = Executors.newSingleThreadExecutor();
        Future<Integer> ketQua = executor2.submit(() -> 10 + 20);
        System.out.println(ketQua.get());   // 30 - .get() chờ và lấy kết quả
        executor2.shutdown();
    }
}
Mẹo
Tự tạo Thread mới liên tục rất tốn tài nguyên. ExecutorService tái sử dụng một nhóm luồng cố định (thread pool) — đây là cách quản lý đa luồng chuẩn mực trong Java thực tế, thay vì tự quản lý Thread thủ công.

Virtual Threads (Java 21+) — bước tiến lớn nhất của Java hiện đại

Thread truyền thống (ở trên) ánh xạ trực tiếp tới thread hệ điều hành — tốn bộ nhớ (mỗi thread ~1MB) nên thường giới hạn ở vài nghìn thread cùng lúc. Từ Java 21 (chính thức ổn định, không còn preview), Java bổ sung Virtual Thread — thread "ảo" siêu nhẹ do JVM quản lý, cho phép chạy HÀNG TRIỆU thread đồng thời mà không cần thay đổi cách viết code:

VirtualThreadDemo.java 
// Chỉ cần đổi 1 dòng so với ExecutorService truyền thống ở trên
try (ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 1; i <= 10_000; i++) {         // 10,000 task chạy đồng thời - vẫn nhẹ nhàng
        int taskId = i;
        executor.submit(() -> {
            System.out.println("Task " + taskId + " chạy trên " + Thread.currentThread());
        });
    }
}   // try-with-resources tự động shutdown() khi kết thúc khối lệnh
Ghi chú
Virtual Thread phù hợp nhất cho các tác vụ I/O-bound (gọi API, truy vấn database, đọc file...) — khi một virtual thread bị block chờ I/O, JVM tự động "mượn" thread hệ điều hành bên dưới cho virtual thread khác dùng, thay vì giữ chết một thread OS quý giá. Với tác vụ nặng tính toán (CPU-bound), thread pool cố định như newFixedThreadPool vẫn phù hợp hơn.
