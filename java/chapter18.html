Java / BÀI 18

Generics

Dùng class/method tổng quát, phân biệt wildcard extends/super, hiểu tính bất biến và giới hạn type erasure.

Làm quiz ở trang riêng

Viết một kiểu hoặc phương thức dùng lại cho nhiều loại dữ liệu mà vẫn để trình biên dịch kiểm tra cách dùng. Bài dùng Java 8 trở lên, nối tiếp kiến thức List của bài 16.

Mục tiêu

  • Phân biệt type parameter (tham số kiểu) và type argument (đối số kiểu).
  • Viết class và method tổng quát, xử lý đầu vào rỗng có chủ đích.
  • Hiểu tính bất biến của List, wildcard (ký tự đại diện kiểu) và giới hạn của type erasure.

Vấn đề thực tế

Bạn cần một hộp lưu tên bài học và một hộp lưu điểm. Nếu cả hai dùng Object, đoạn đọc phải ép kiểu; một chỗ ghi nhầm loại dữ liệu có thể làm đoạn đọc hỏng lúc chạy. Nếu viết riêng hai class gần giống nhau, mỗi lần sửa phải sửa hai nơi. Generics cho phép mô tả một Hop<T> và chọn T khi sử dụng.

Lý thuyết nền

Tham số kiểu và kiểm tra lúc biên dịch

Trong khai báo Hop<T>, T là tên tham số kiểu do bạn đặt. Trong Hop<String>, String là đối số kiểu cụ thể. T không phải tên biến và không phải từ khóa đặc biệt; E thường chỉ phần tử, K/V thường chỉ khóa/giá trị. Cú pháp diamond <> cho phép compiler suy ra đối số từ ngữ cảnh.

Đối số kiểu phải là reference type (kiểu tham chiếu): dùng Integer thay cho int, Double thay cho double. Autoboxing tự chuyển giá trị nguyên thủy sang đối tượng wrapper tương ứng khi cần. Generics giúp phát hiện nhiều lỗi kiểu lúc biên dịch, không bảo đảm dữ liệu khác null hoặc mọi lỗi runtime đều biến mất.

Generic method và ràng buộc

Method có thể khai báo tham số kiểu riêng bằng <T> trước kiểu trả về. Ví dụ static <T> T dau(List<T> ds) liên hệ kiểu phần tử đầu vào và giá trị trả ra. Một method static không dùng trực tiếp tham số T của class bao ngoài; hãy khai báo tham số kiểu riêng nếu cần. Với <T extends Number>, compiler chỉ nhận đối số kiểu là Number hoặc lớp con và cho phép gọi các method của Number.

List<Integer> không phải List<Number>

Integer kế thừa Number, nhưng quan hệ này không tự chuyển sang List: generic type như List là invariant (bất biến về đối số kiểu). Nếu một List<Integer> được dùng như List<Number> có thể ghi, người khác có thể thêm Double vào nó. Vì vậy phép gán như thế bị từ chối. Có thể đưa một Integer vào List<Number>, nhưng đó là thao tác với phần tử, không phải gán cả danh sách.

Chọn kiểu theo thao tác của method

List<T>
Đọc được T; thêm được T nếu danh sách hỗ trợ sửa.
List<? extends Number>
Đọc được Number; không thêm được giá trị Number cụ thể khác null qua tham chiếu này.
List<? super Integer>
Đọc chỉ bảo đảm Object; thêm được Integer nếu danh sách hỗ trợ sửa.
List<?>
Đọc được Object; không biết kiểu phần tử để thêm giá trị khác null.

PECS là mẹo nhớ Producer Extends, Consumer Super: đầu vào cung cấp giá trị để đọc thì cân nhắc extends; nơi nhận giá trị để ghi thì cân nhắc super. Đây không phải luật dùng wildcard cho mọi tham số. Wildcard không biến danh sách thành bất biến: bạn vẫn có thể gọi clear nếu implementation cho phép. Những mô tả thêm phần tử ở trên là quy tắc kiểu, không hứa mọi implementation đều hỗ trợ add.

Ví dụ có thể chạy

Mỗi khối là một chương trình độc lập, có main và import đầy đủ, dùng JDK 8 trở lên. Lưu đúng tên tệp; chạy javac -encoding UTF-8 GenericBoxDemo.java rồi java GenericBoxDemo. Ví dụ sau thay tên bằng WildcardDemo. Chú thích sau lệnh in là output dự kiến để tự đối chiếu.

GenericBoxDemo.java
import java.util.Arrays;
import java.util.Collections;
import java.util.List;
import java.util.Objects;

public class GenericBoxDemo {
    static class Hop<T> {
        private T noiDung;
        Hop(T noiDung) { this.noiDung = noiDung; }
        void dat(T noiDung) { this.noiDung = noiDung; }
        T lay() { return noiDung; }
    }

    static <T> T dau(List<T> ds) {
        Objects.requireNonNull(ds, "ds");
        if (ds.isEmpty()) {
            throw new IllegalArgumentException("Danh sach rong");
        }
        return ds.get(0);
    }

    public static void main(String[] args) {
        Hop<String> ten = new Hop<>("Java");
        ten.dat("Generics");
        String bai = ten.lay();
        System.out.println(bai); // Generics
        Hop<Integer> diem = new Hop<>(8);
        System.out.println(diem.lay()); // 8
        System.out.println(dau(Arrays.asList(4, 7, 4))); // 4
        try {
            dau(Collections.<String>emptyList());
        } catch (IllegalArgumentException e) {
            System.out.println(e.getMessage()); // Danh sach rong
        }
    }
}
  1. Hop có T ở field, constructor, method ghi và method đọc. Nhờ dùng cùng T, hộp String chỉ nhận giá trị tương thích String.
  2. Hop<Integer> nhận 8 nhờ autoboxing. lay trả đúng kiểu đã khai báo nên không cần ép từ Object.
  3. <T> trước kiểu trả về của dau khai báo tham số kiểu riêng. Với danh sách số nguyên, T được suy ra là Integer.
  4. requireNonNull từ chối tham chiếu danh sách null. Nhánh isEmpty ném lỗi có thông báo trước khi get(0); try/catch trong main kiểm tra chính trường hợp này. Hàm không loại bỏ phần tử null nếu bản thân danh sách chứa null.
WildcardDemo.java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class WildcardDemo {
    static double tong(List<? extends Number> nguon) {
        double total = 0;
        for (Number n : nguon) {
            total += n.doubleValue();
        }
        return total;
    }

    static void themDiem(List<? super Integer> dich) {
        dich.add(7);
        dich.add(9);
    }

    public static void main(String[] args) {
        List<Integer> soNguyen = Arrays.asList(1, 2, 3);
        List<Double> soThuc = Arrays.asList(1.5, 2.5);
        System.out.println(tong(soNguyen)); // 6.0
        System.out.println(tong(soThuc));   // 4.0
        System.out.println(tong(new ArrayList<Integer>())); // 0.0
        List<Number> dich = new ArrayList<>();
        themDiem(dich);
        System.out.println(dich); // [7, 9]
        List<? super Integer> gocNhin = dich;
        Object dauTien = gocNhin.get(0);
        System.out.println(dauTien); // 7
    }
}
  1. tong chỉ cần đọc Number, nên nhận được cả List<Integer> và List<Double> qua ? extends Number. Không cần ép cả danh sách thành List<Number>.
  2. total bắt đầu bằng 0 nên danh sách rỗng trả 0.0. Quy ước đầu vào của tong là danh sách và các phần tử đều khác null; tổng dùng double nên có thể có sai số với số thập phân.
  3. themDiem ghi Integer nên nhận ? super Integer, bao gồm List<Integer>, List<Number> và List<Object>. dich là ArrayList hỗ trợ add.
  4. Khi nhìn qua List<? super Integer>, đọc chỉ bảo đảm Object: không được tự giả định mọi phần tử là Integer, vì danh sách gốc có thể chứa Number khác.

Lỗi thường gặp và giới hạn

  • Dùng raw type như Hop không có <T> làm mất một phần kiểm tra kiểu, có thể tạo cảnh báo unchecked và lỗi ép kiểu. Giữ đối số kiểu, đọc cảnh báo thay vì tắt bằng annotation.
  • Type erasure (xóa kiểu khi biên dịch) thay tham số kiểu bằng bound hoặc Object và chèn cast khi cần. Không có class runtime riêng cho mỗi đối số kiểu; không dùng instanceof List<String> để kiểm tra kiểu phần tử, có thể dùng instanceof List<?>.
  • Không viết Hop<int>, new T() hoặc new T[10] trong kiểu tổng quát thông thường. Nhận giá trị qua constructor như ví dụ; dùng wrapper cho primitive.
  • Không nhầm ? extends Number là danh sách cho phép thêm mọi Number, hoặc ? super Integer là danh sách đọc được Integer chắc chắn.
  • Hai overload nhận List<String> và List<Integer> với cùng tên và không có tham số khác bị trùng chữ ký sau erasure. Đặt tên diễn đạt mục đích hoặc thiết kế một method tổng quát.

Bài tập ba mức

  1. Cơ bản: tạo Hop<String> chứa SQL rồi đổi thành Java; tạo Hop<Integer> chứa 10. Tự kiểm: lần lượt in Java và 10, không dùng cast.
  2. Vận dụng: dùng dau với [2, 2], ["A"] và danh sách rỗng. Tự kiểm: trả 2, trả A, rồi ném IllegalArgumentException theo hợp đồng; thử null thì nhận NullPointerException từ requireNonNull.
  3. Nâng cao: viết method <T> void chep(List<? extends T> nguon, List<? super T> dich), thêm từng phần tử nguồn vào đích. Quy ước hai danh sách khác đối tượng, không null và đích hỗ trợ add. Tự kiểm: [1, 1, 2] sang List<Number> rỗng giữ đủ [1, 1, 2]; nguồn rỗng không đổi đích; nguồn [3] và đích [9] thành [9, 3]. Giải thích extends/super và vì sao không cần cast.

Tóm tắt

Generics liên hệ các vị trí dùng cùng kiểu và đưa nhiều lỗi về lúc biên dịch. Dùng <T> khi cần gọi tên mối quan hệ kiểu; chọn wildcard theo hướng đọc/ghi. List<Integer> không phải List<Number>. Xử lý null, danh sách rỗng và khả năng sửa vẫn là trách nhiệm của hợp đồng method.
