Chương 2 — Cài đặt JDK & IDE

Chuẩn bị môi trường học Java, xác nhận đúng công cụ và chạy thử trước khi dựa vào nút Run của IDE.

1. Mục tiêu học

  • Phân biệt JVM, runtime và bộ công cụ phát triển JDK.
  • Kiểm tra java, javac, PATH và phiên bản mà terminal đang sử dụng.
  • Chạy chương trình kiểm tra môi trường rồi cấu hình trình soạn thảo phù hợp.

2. Vấn đề thực tế

Bạn bấm Run trong IDE và chương trình chạy, nhưng terminal báo không tìm thấy javac. Bạn học khác có java phiên bản cũ dù đã cài JDK mới. Cả hai tình huống có thể xuất phát từ việc mỗi công cụ đang chọn một đường dẫn khác nhau.

Thay vì cài lại nhiều lần, hãy kiểm tra tuần tự: phần mềm có tồn tại không, terminal đang tìm ở đâu, và IDE đang dùng JDK nào? Một chương trình nhỏ cùng bản ghi phiên bản sẽ giúp bạn trao đổi lỗi chính xác hơn ảnh chụp nút Run.

3. Lý thuyết nền

JVM là thành phần thực thi bytecode. Runtime gồm JVM và những thư viện, thành phần cần khi chạy. JDK cung cấp công cụ phát triển, nổi bật là javac, cùng môi trường chạy. Cách đóng gói runtime phụ thuộc bản phân phối; đừng mặc định JDK hiện đại luôn có một thư mục jre riêng.

PATH là danh sách nơi hệ điều hành tìm executable khi bạn gõ tên lệnh. JAVA_HOME thường trỏ tới thư mục gốc JDK để công cụ phát triển sử dụng; tự đặt biến này không bảo đảm lệnh java đã đổi. Bạn vẫn cần kiểm tra PATH và cấu hình riêng của IDE.

Ví dụ của đợt này được kiểm tra bằng JDK 21, đồng thời biên dịch nhắm Java 8. Bạn có thể dùng JDK 21 làm môi trường thống nhất cho khóa học; đây là lựa chọn thực hành của bài, không phải yêu cầu rằng mọi dự án Java đều phải dùng phiên bản đó.

4. Ví dụ từng bước

A. Chuẩn bị và kiểm tra công cụ

Từ trang chính thức của bản phân phối như Eclipse Temurin, chọn JDK phù hợp hệ điều hành và kiến trúc máy. Đọc hướng dẫn của gói cài đặt; bản archive cần giải nén vào thư mục ổn định. Không chọn runtime-only nếu mục tiêu là biên dịch mã.

  1. Cài hoặc giải nén JDK; ghi lại thư mục chứa bin/java và bin/javac.
  2. Mở terminal mới sau khi thay cấu hình, tránh dùng phiên làm việc vẫn giữ môi trường cũ.
  3. Chạy hai lệnh dưới đây. Cả hai phải được tìm thấy; đọc dòng phiên bản, không chỉ kiểm tra có chữ Java.
Terminal — kiểm tra JDK
java -version
javac -version

Lệnh thứ nhất báo phiên bản runtime; lệnh thứ hai báo trình biên dịch. Số bản vá có thể khác ví dụ trong tài liệu, nhưng nếu một lệnh là Java 8 và lệnh kia là Java 21, hãy kiểm tra lại lựa chọn đường dẫn trước khi tiếp tục.

Trên PowerShell, dùng Get-Command java,javac để xem executable được chọn. Trên macOS/Linux, dùng command -v java và command -v javac. Những lệnh này dùng cú pháp riêng của shell; không dán lệnh PowerShell vào Bash hoặc ngược lại.

B. Xác nhận môi trường bằng chương trình

Tạo thư mục làm bài riêng, lưu file dưới đây thành EnvironmentCheck.java. Chạy từ chính thư mục đó để tách lỗi đường dẫn khỏi lỗi lập trình.

EnvironmentCheck.java
public class EnvironmentCheck {
    public static void main(String[] args) {
        System.out.println("Compiler and runtime are ready");
        System.out.println(System.getProperty("java.version"));
    }
}
  1. Dòng đầu khai báo lớp public; tên lớp quyết định tên file trong ví dụ.
  2. Dòng main tạo điểm bắt đầu chương trình, giữ nguyên chữ ký này khi thử môi trường.
  3. Dòng in thông báo xác nhận mã đã biên dịch và được thực thi đến vị trí đó.
  4. Dòng getProperty đọc phiên bản runtime đang chạy chương trình, rồi in nó ra. Đây không phải cách hỏi phiên bản javac.
  5. Hai dấu ngoặc cuối đóng phương thức và lớp; không bỏ chúng khi sao chép.
Terminal — biên dịch và chạy
javac EnvironmentCheck.java
java EnvironmentCheck

Kết quả đầu là Compiler and runtime are ready; dòng sau là phiên bản của runtime trên máy. Không cần khớp một số bản vá cố định. Kiểm tra file EnvironmentCheck.class được tạo, rồi ghi phiên bản vào ghi chú thực hành.

C. Dùng IDE sau khi terminal hoạt động

Mở thư mục làm bài trong IDE thay vì chỉ mở một file rời. Với VS Code, dùng các Java extension theo hướng dẫn chính thức và kiểm tra JDK mà chúng chọn. Với IDE khác, tìm cấu hình JDK của dự án. Chạy cùng file kiểm tra, đối chiếu dòng phiên bản với terminal.

5. Lỗi thường gặp

  • Chỉ cài runtime: java chạy nhưng javac thiếu. Kiểm tra lại gói tải trước khi chỉnh PATH.
  • PATH ưu tiên bản cũ: kiểm tra đường dẫn thực tế, không dựa riêng vào tên thư mục mới cài.
  • JAVA_HOME trỏ tới bin thay vì thư mục gốc JDK: sửa theo yêu cầu công cụ rồi kiểm tra lại.
  • Chỉnh biến môi trường nhưng không mở terminal mới: phiên cũ có thể chưa nhận cấu hình mới.
  • Tải gói sai kiến trúc hoặc dùng nguồn không rõ: xác nhận thông tin máy và lấy hướng dẫn từ nhà phân phối.

6. Bài tập ba mức

Dễ — Ghi phiên bản

Chạy hai lệnh kiểm tra và lưu đầu ra vào ghi chú. Ghi executable mà terminal chọn. Tiêu chí đạt: xác định được cả công cụ chạy và biên dịch.

Vừa — So sánh terminal và IDE

Chạy EnvironmentCheck ở cả hai nơi. So sánh phiên bản; nếu khác, tìm cấu hình JDK của IDE. Không đổi toàn hệ thống chỉ để làm hai kết quả giống nhau.

Khó — Hướng dẫn tái lập

Viết checklist cho máy mới: hệ điều hành, kiến trúc, nguồn JDK, đường dẫn, phiên bản và các bước kiểm tra. Nhờ bạn học làm theo, hoặc thử trong thư mục mới; ghi rõ phần chưa kiểm chứng.

7. Tóm tắt

Cài JDK đúng gói, xác nhận java và javac rồi chạy chương trình nhỏ. PATH, JAVA_HOME và lựa chọn JDK của IDE là những cấu hình liên quan nhưng không đồng nhất.
