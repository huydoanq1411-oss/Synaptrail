Chương 1 — Giới thiệu Java

Hiểu đường đi từ mã nguồn đến chương trình chạy được, trước khi học cú pháp và viết ứng dụng lớn.

1. Mục tiêu học

  • Phân biệt mã nguồn, bytecode, JVM và công cụ biên dịch.
  • Giải thích khả năng chạy trên nhiều hệ điều hành cùng những giới hạn thực tế.
  • Đọc một chương trình nhỏ, dự đoán đầu ra và thử thay đổi thông báo.

Không cần biết Java trước khi đọc bài này. Bạn chỉ cần thao tác với file văn bản và mở terminal. Nếu máy chưa có JDK, hãy đọc chương 2 trước khi thực hành, rồi quay lại các ví dụ dưới đây.

2. Vấn đề thực tế

Một nhóm làm công cụ in thông báo nhận hàng cho cửa hàng. Người viết mã dùng Windows, người kiểm thử dùng Linux. Nhóm muốn giữ một bộ mã nguồn, thay vì viết lại toàn bộ chương trình cho từng máy. Đây là tình huống phù hợp để hiểu vai trò của Java và máy ảo.

Hãy chia công việc thành hai bước: chuyển văn bản chương trình sang dạng JVM hiểu được, rồi nhờ JVM thực thi. Khi kết quả không xuất hiện, việc biết hai bước này giúp bạn hỏi đúng câu: biên dịch chưa thành công, hay chương trình đã chạy nhưng làm sai điều mong muốn?

3. Lý thuyết nền

Java vừa là tên ngôn ngữ, vừa gắn với một hệ sinh thái công cụ và thư viện. File có đuôi .java chứa mã nguồn để con người đọc và sửa. Trình biên dịch javac kiểm tra mã rồi tạo file .class chứa bytecode; lệnh java khởi động JVM để chạy lớp được chỉ định.

JVM có bản triển khai phù hợp với từng hệ điều hành và kiến trúc máy. Vì thế bytecode có thể được dùng trên nhiều môi trường có runtime tương thích. Điều này không có nghĩa mọi chương trình tự động chạy trên mọi thiết bị: phiên bản runtime, thư viện phụ thuộc và những thành phần riêng của hệ điều hành vẫn quan trọng.

Java hỗ trợ lập trình hướng đối tượng nhưng cũng có kiểu nguyên thủy như int và boolean. Bạn không cần hiểu toàn bộ OOP để chạy chương trình đầu tiên. Trong đợt học này, hãy xem lớp là nơi tổ chức mã; các chương sau sẽ giải thích đối tượng, phương thức và trách nhiệm của từng lớp.

Một giới hạn cần nhớ

Bytecode tạo cho phiên bản Java mới hơn không mặc nhiên chạy được trên runtime cũ. Khi chia sẻ chương trình, hãy ghi rõ phiên bản dùng để biên dịch và chạy; đừng chỉ nói “máy có Java”.

4. Ví dụ từng bước

Ví dụ mô phỏng thông báo nhận hàng, chưa dùng nhập liệu hoặc cơ sở dữ liệu. Lưu đúng tên WelcomeJava.java. Mỗi dòng có một nhiệm vụ đơn giản để bạn quan sát được toàn bộ quá trình.

WelcomeJava.java
public class WelcomeJava {
    public static void main(String[] args) {
        System.out.println("Welcome to Java");
        System.out.println("Order received");
    }
}
  1. Dòng đầu đặt tên lớp công khai. Với cách tổ chức này, tên file phải là WelcomeJava.java, phân biệt chữ hoa và chữ thường.
  2. Dòng thứ hai khai báo main, điểm bắt đầu mà lệnh java sẽ gọi. Tạm giữ nguyên chữ ký; chương 3 sẽ giải thích từng thành phần.
  3. Dòng thứ ba in lời chào rồi xuống dòng. Văn bản trong dấu nháy kép là dữ liệu, không phải câu lệnh Java.
  4. Dòng thứ tư in thông báo nhận hàng. Nó chạy sau dòng chào vì hai lệnh được viết theo thứ tự.
  5. Dấu ngoặc đóng đầu tiên kết thúc main; dấu còn lại kết thúc lớp. Cặp ngoặc mở và đóng xác định phạm vi mã.
Terminal — chạy trong thư mục chứa file
javac WelcomeJava.java
java WelcomeJava

Lệnh đầu biên dịch; nếu thành công, xuất hiện WelcomeJava.class. Lệnh thứ hai chạy tên lớp, không thêm đuôi .class. Kết quả là hai dòng: Welcome to Java, rồi Order received. Không cần mạng hoặc thư viện ngoài để thực hiện ví dụ này.

Đổi thông báo nhận hàng thành “Order ready”, lưu file và chạy lại cả hai lệnh. Nếu chỉ chạy lệnh java, bạn có thể vẫn thấy kết quả cũ vì JVM đang dùng file class đã biên dịch trước đó. Thử nghiệm này giúp phân biệt việc sửa mã với việc cập nhật chương trình chạy.

Trước khi mở rộng ví dụ, tự trả lời ba câu hỏi: file nào là đầu vào của trình biên dịch, file nào được tạo ra và lệnh nào thực thi chương trình? Nếu chưa chắc, kiểm tra danh sách file sau mỗi bước thay vì đoán từ giao diện của IDE.

5. Lỗi thường gặp

  • Nhầm Java với JavaScript vì tên gần nhau: đây là hai ngôn ngữ khác nhau, không dùng chung trình biên dịch hoặc quy tắc cú pháp.
  • Cho rằng bytecode là mã nguồn: sửa file .java và biên dịch lại; không mở file .class để chỉnh như văn bản.
  • Thấy lệnh java chạy được rồi kết luận đã đủ công cụ phát triển: kiểm tra thêm javac; runtime đơn lẻ có thể thiếu trình biên dịch.
  • Khẳng định Java “hoàn toàn hướng đối tượng”: ghi nhớ các kiểu nguyên thủy và học mô hình thực tế thay vì khẩu hiệu.

6. Bài tập ba mức

Dễ — Đổi thông báo

Đổi dòng chào thành “Hello Synaptrail”, giữ dòng nhận hàng. Biên dịch và chạy lại; kết quả phải có đúng hai dòng. Ghi rõ file bạn đã sửa và file được tạo.

Vừa — Thử kết quả cũ

Biên dịch bản gốc, sửa nội dung mà chưa biên dịch lại, rồi chạy. So sánh với kết quả sau khi biên dịch mới. Giải thích sự khác nhau, không xóa file class trước thử nghiệm.

Khó — Hướng dẫn bàn giao

Viết checklist để bạn học chạy chương trình từ mã nguồn trên máy khác: công cụ, phiên bản, tên file, thư mục và lệnh. Nếu có máy thứ hai, kiểm chứng; nếu không, dùng thư mục mới và ghi giới hạn thử nghiệm.

7. Tóm tắt

Mã nguồn .java được javac biên dịch thành bytecode .class; JVM thực thi bytecode khi bạn chạy lệnh java. Khả năng đa nền tảng cần môi trường tương thích. Học bằng cách dự đoán, chạy và quan sát file tạo ra.

4. Muốn bàn giao bytecode cho máy khác, cần kiểm tra điều gì?

  • C. Sai: Tên người dùng không bảo đảm môi trường tương thích.
  • D. Đúng: bài nêu phiên bản, phụ thuộc và hệ điều hành.

Giải thích đáp án

  • D. Sai: Không cần đổi ngôn ngữ để sửa thông báo.
