File System (fs module)

Đọc JSON, kiểm dữ liệu và tạo file không ghi đè bằng Node.js; thực hành trong thư mục tạm riêng.

Làm quiz ở trang riêng

1. Mục tiêu học

Sau bài, bạn đọc được file UTF-8 bằng node:fs/promises, phân biệt dữ liệu JSON với object JavaScript, xử lý file chưa tồn tại và tạo file mà không ghi đè bản cũ. Cần biết async/await, Promise, object và CommonJS. Ví dụ dùng Node.js 24.x, đuôi .cjs, không cần npm install. Đây là bài Node chạy trong terminal, không phải script chạy trong trình duyệt.

Ranh giới bài thực hành

Ví dụ tạo thư mục thử riêng trong vùng tạm của hệ điều hành. Không đọc localStorage, không nhập dữ liệu tiến độ thật của Synaptrail và không sửa website. File JSON có schema riêng để học, không tương thích trực tiếp với chức năng nhập tiến độ của site. Chỉ một chương mẫu được nâng cấp.

2. Vấn đề thực tế

Trong bài REST API, Map mất khi tiến trình kết thúc. Một công cụ học local có thể xuất bản chụp tiến độ ra JSON để mở lại sau. Nhưng ghi file không chỉ là gọi writeFile: chạy từ terminal khác có thể trỏ nhầm thư mục, dữ liệu JSON hợp lệ có thể sai cấu trúc và một lần chạy lại có thể xóa nội dung cũ nếu dùng chế độ ghi mặc định.

Ta làm một công cụ nhỏ: chưa có file thì đọc ra danh sách rỗng; tạo một bản chụp mới; đọc lại; từ chối tạo lần hai cùng tên. Bài cố tình chưa cập nhật file có sẵn, chưa xử lý nhiều người ghi và chưa biến file thành database.

3. Lý thuyết nền

Promise, callback và synchronous

node:fs có API callback và synchronous; node:fs/promises trả Promise để dùng await. Callback vẫn được Node hỗ trợ, không phải API bị loại bỏ. Promise giúp viết luồng tuần tự dễ đọc; nó không khiến thao tác I/O hoàn tất ngay. Các hàm đồng bộ như readFileSync chặn luồng đang chạy trong lúc đọc, nên cần cân nhắc khi dùng trong request handler. Trong bài ta dùng await để lần đọc diễn ra sau khi lần ghi hoàn tất.

Đường dẫn và encoding

Đường dẫn tương đối như progress.json được giải theo thư mục làm việc hiện tại, không tự động theo nơi đặt script. path.join ghép các đoạn theo quy tắc hệ điều hành, tránh tự viết dấu phân cách Windows. os.tmpdir trả vùng tạm; mkdtemp tạo một thư mục tên riêng từ tiền tố. Không nối đường dẫn nhận từ người dùng rồi cho rằng path.join đã chống được truy cập ra ngoài thư mục: hàm này không phải cơ chế phân quyền.

readFile không chỉ định encoding trả Buffer, tức vùng byte; dùng utf8 để nhận chuỗi. JSON.parse chuyển chuỗi JSON thành giá trị JavaScript, nhưng không kiểm schema nghiệp vụ. JSON.stringify chuyển object thành văn bản để lưu. JSON rỗng hoặc sai cú pháp không phải “file chưa tồn tại”.

Tạo mới khác ghi đè

writeFile mặc định có thể thay nội dung file đã có. Cờ wx yêu cầu tạo mới độc quyền: file đã tồn tại thì báo EEXIST. Không kiểm exists rồi mới ghi để thay cho wx, vì một tiến trình khác có thể tạo file giữa hai bước. wx không bảo đảm một lần ghi dài không bị dở dang khi máy mất điện; nó cũng không phải transaction hoặc cơ chế khóa cho cập nhật nhiều người.

Tình huốngXử lý trong mẫu
ENOENT khi đọcTrả dữ liệu ban đầu; không tự ghi file
EEXIST khi tạoTừ chối ghi đè, giữ bản cũ

4. Ví dụ hoàn chỉnh và giải thích

Lưu mã dưới thành doc-tien-do.cjs trong thư mục thực hành riêng. Chạy bằng Node, không dán vào console trình duyệt. Mỗi lần chạy tạo một thư mục thử mới; đường dẫn thật được in ra để bạn xem file. Dữ liệu có thể bị hệ điều hành dọn khỏi vùng tạm, vì vậy đây không phải nơi lưu bản sao quan trọng lâu dài.

doc-tien-do.cjs
'use strict';
const fs = require('node:fs/promises');
const path = require('node:path');
const os = require('node:os');

function validate(value) {
  if (!value || typeof value !== 'object' || Array.isArray(value)) {
    throw new Error('INVALID_PROGRESS');
  }
  if (value.version !== 1 || !Array.isArray(value.completed)) {
    throw new Error('INVALID_PROGRESS');
  }
  if (value.completed.length > 100 || !value.completed.every(
    id => typeof id === 'string' && /^chapter\d{2}$/.test(id)
  )) throw new Error('INVALID_PROGRESS');
  return { version: 1, completed: [...new Set(value.completed)] };
}
async function readProgress(file) {
  let text;
  try {
    text = await fs.readFile(file, 'utf8');
  } catch (error) {
    if (error.code === 'ENOENT') return { version: 1, completed: [] };
    throw error;
  }
  return validate(JSON.parse(text));
}
async function createProgress(file, value) {
  const normalized = validate(value);
  const text = JSON.stringify(normalized, null, 2) + '\n';
  await fs.writeFile(file, text, { encoding: 'utf8', flag: 'wx' });
  return normalized;
}
async function main() {
  const directory = await fs.mkdtemp(path.join(os.tmpdir(), 'synaptrail-fs-'));
  const file = path.join(directory, 'progress.json');
  console.log('File thử riêng:', file);
  console.log('Trước tạo:', await readProgress(file));
  await createProgress(file, {
    version: 1, completed: ['chapter22', 'chapter22', 'chapter24'],
  });
  console.log('Sau tạo:', await readProgress(file));
  try {
    await createProgress(file, { version: 1, completed: [] });
  } catch (error) {
    if (error.code !== 'EEXIST') throw error;
    console.log('Đã từ chối ghi đè file có sẵn.');
  }
  console.log('Dữ liệu còn nguyên:', await readProgress(file));
}
if (require.main === module) {
  main().catch(error => {
    console.error('Không hoàn tất:', error.code || error.message);
    process.exitCode = 1;
  });
}
module.exports = { validate, readProgress, createProgress };
Terminal — trong thư mục chứa ví dụ
node --version
node doc-tien-do.cjs
  1. Ba require nạp module có sẵn. Tiền tố node: làm rõ nguồn thư viện; .cjs xác định CommonJS kể cả khi thư mục ngoài có package.json dùng type module.
  2. validate từ chối null, mảng, version khác 1 và completed không phải mảng. Giới hạn 100 phần tử là hợp đồng của mẫu; chapterNN chỉ là định dạng, chưa xác nhận chương đó thực sự tồn tại trong website.
  3. every kiểm từng ID, Set loại trùng và trả object mới chỉ có hai trường được chấp nhận. Đầu vào có trường khác không được sao chép tùy tiện. Không sửa object đầu vào.
  4. readProgress chỉ bắt lỗi từ thao tác đọc. Riêng ENOENT trở thành trạng thái ban đầu; lỗi khác được ném lại. JSON.parse và validate nằm ngoài catch đọc nên dữ liệu hỏng không bị hiểu thành file thiếu.
  5. createProgress kiểm dữ liệu trước khi chạm file, tuần tự hóa rồi await writeFile với wx. Nếu tên đã tồn tại, Promise bị reject; không ghi đè để “sửa” lỗi.
  6. main tạo thư mục riêng rồi dùng path.join đặt tên cố định progress.json. Không nhận đường dẫn tùy ý từ request, không dùng dữ liệu thật của bạn.
  7. Lần tạo thứ hai cố tình gặp EEXIST. Nhánh catch chỉ chấp nhận lỗi này; bất kỳ lỗi khác vẫn làm main thất bại. Đọc cuối cùng chứng minh dữ liệu trước đó còn nguyên.
  8. require.main chỉ chạy minh họa khi gọi file trực tiếp; module.exports cho phép kiểm thử hàm mà không tự chạy main. Catch cuối đặt exitCode 1 khi thất bại thay vì in thông báo thành công giả.

Kết quả mong đợi: lần đọc đầu có completed rỗng; lần sau có chapter22 và chapter24 mỗi ID một lần; lần tạo lặp báo từ chối ghi đè; lần đọc cuối vẫn hai ID. Đường dẫn thư mục tạm thay đổi giữa các lần chạy. Mở progress.json sẽ thấy JSON có version 1 và completed, không phải đoạn mã JavaScript cần thực thi.

5. Lỗi thường gặp

  • Không thấy file: đọc đường dẫn được in, đừng tìm theo thư mục terminal một cách suy đoán.
  • Nhận Buffer thay chuỗi: kiểm tham số utf8. Không tự đổi encoding để che lỗi dữ liệu nguồn.
  • Quên await: lần đọc có thể chạy trước ghi, catch bên ngoài không nhận rejection như mong muốn.
  • Catch mọi lỗi rồi trả []: cách này che JSON hỏng và quyền truy cập. Chỉ ENOENT có chính sách mặc định trong mẫu.
  • Dùng Promise.all để ghi cùng file: API Promise không tự tuần tự hóa hay khóa dữ liệu; mẫu không hỗ trợ cập nhật đồng thời.
  • Tưởng file là database: không có transaction, truy vấn nhiều bản ghi hoặc bảo đảm phục hồi sau mất điện. Xem bài MySQL để học tầng lưu trữ khác.

6. Bài tập ba mức

Dễ

Chạy ví dụ, mở đúng file được in ra, giải thích vì sao ID trùng chỉ còn một lần. Chạy lại: vì sao có đường dẫn mới và bản cũ không bị ghi đè? Không sửa file tiến độ thật của site.

Vừa

Trong thư mục thử riêng, tạo bản JSON sai cú pháp và bản đúng cú pháp nhưng completed là chuỗi. Gọi readProgress và ghi nhận hai loại lỗi. Chứng minh nội dung file vẫn nguyên sau lỗi; không thay catch bằng reset dữ liệu.

Khó

Kiểm thử bằng node:assert/strict: file thiếu, tên có sẵn, ID sai mẫu, 100/101 phần tử và đầu vào không bị sửa. Thử hai createProgress cùng tên bằng Promise.allSettled trong thư mục mới: dự đoán một thành công, một EEXIST, rồi đọc bản cuối. Giải thích điều này chưa chứng minh cập nhật đồng thời hoặc chịu mất điện.

7. Tóm tắt

Đọc file là đọc byte/văn bản; parse JSON và kiểm schema là hai bước khác nhau. Đường dẫn cần rõ ràng; await xác định thứ tự trong luồng của bạn. Tạo mới bằng wx tránh ghi đè bản có sẵn, còn lỗi I/O phải được phân loại. Mẫu chỉ tạo bản chụp local, không đồng bộ với localStorage hay thay database của ứng dụng.
