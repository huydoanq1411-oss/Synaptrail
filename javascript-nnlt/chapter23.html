Express — Server cơ bản

Khởi động Express local, kiểm params/query và trả text/JSON với status rõ ràng; nền tảng trước REST API.

Làm quiz ở trang riêng

1. Mục tiêu học

Sau bài, bạn tạo được ứng dụng Express, mở cổng local, định nghĩa route GET và trả text/JSON. Bạn phân biệt route parameter (tham số đường dẫn), query string (tham số truy vấn), dữ liệu không hợp lệ và tài nguyên không tồn tại. Cần biết hàm, object, mảng, CommonJS, Promise và thao tác terminal; xem lại npm nếu chưa biết dependency là gì.

Phạm vi phiên bản: Node.js 24.x, Express 5.x, file .cjs. Đây là môi trường mục tiêu của ví dụ, không phải khẳng định phiên bản mới nhất. Tham khảo tài liệu chính thức cuối bài khi đổi major version. Synaptrail vẫn là website tĩnh; server bên dưới là bài thực hành riêng.

2. Vấn đề thực tế

Frontend muốn mở hồ sơ sinh viên ID 1 hoặc xem trang thứ hai của danh sách. Một hàm luôn trả tên Huy cho mọi ID có thể minh họa JSON, nhưng khiến người học tưởng server đã tra cứu dữ liệu. Ta dùng hai sinh viên cố định trong bộ nhớ: ID 1 và 2. ID 99 không tồn tại; abc không phải ID hợp lệ. Hai lỗi này cần phản hồi khác nhau để client hiểu chuyện gì xảy ra.

Trước khi xây CRUD hay nối MySQL, cần trả lời ba câu: request nào được route nhận, dữ liệu đầu vào nằm ở đâu, và server kết thúc response thế nào? Mẫu chỉ đọc dữ liệu công khai giả lập, không có ghi dữ liệu, tài khoản hoặc quyền truy cập. Nó chưa phải dịch vụ production.

3. Lý thuyết nền

Ứng dụng khác server đang lắng nghe

express() tạo app chứa cấu hình và handler. app.get đăng ký xử lý cho method GET cùng mẫu đường dẫn. app.listen mới mở HTTP server trên cổng; chỉ tạo app chưa làm URL truy cập được. Handler nhận req (request — yêu cầu) và res (response — phản hồi). Trình duyệt thanh địa chỉ gửi GET; query string không đổi method thành POST.

Params, query và body

NguồnVí dụCách hiểu
req.params.id/sinh-vien/2Giá trị khớp vị trí :id; cần kiểm định dạng và chuyển số
req.query.trang/sinh-vien?trang=2Điều khiển trang danh sách; không phải ID sinh viên
req.bodyPayload gửi trong requestMuốn nhận JSON cần middleware parser; bài chỉ GET nên chưa dùng

Đừng gọi Number rồi chấp nhận mọi kết quả: chuỗi rỗng, số âm, số thập phân hay số vượt giới hạn chính xác cần chính sách rõ. Query là đầu vào không tin cậy, không bảo đảm luôn là một chuỗi; tham số lặp có thể tạo giá trị khác tùy query parser. Mẫu chỉ nhận một chuỗi số dương chuẩn; thiếu trang thì mặc định 1, giới hạn tối đa 1000.

Status và kết thúc phản hồi

200 là thành công; 400 dùng khi ID hoặc trang sai định dạng; 404 khi không tìm thấy sinh viên hoặc route; 500 cho lỗi xử lý bất ngờ. Trang danh sách hợp lệ nhưng hết kết quả trả 200 với items rỗng, không biến thành lỗi ID. res.json gửi JSON và kết thúc phản hồi. return ở nhánh lỗi giúp JavaScript không chạy tiếp tới lần gửi thứ hai; nó không phải lệnh tạo response riêng.

Middleware là hàm nằm trong luồng xử lý request. app.use cuối chuỗi ở mẫu trả 404 khi các route trên không xử lý. Error middleware có bốn tham số, đặt sau route; lỗi đồng bộ được Express chuyển tới nó. Trong Express 5, Promise bị reject từ handler trả Promise cũng được chuyển tiếp; lỗi phát sinh trong callback tách rời vẫn cần truyền đúng cách, không phải mọi lỗi trong tiến trình đều tự được bắt. Bài này chỉ dùng handler đồng bộ; xem sâu hơn ở REST API và Middleware.

Lưu mã dưới thành server.cjs. File .cjs dùng CommonJS kể cả khi thư mục ngoài có type module. Dữ liệu An/Bình là dữ liệu mẫu viết trong code; không được lấy dữ liệu cá nhân thật để thử public.

server.cjs
'use strict';
function parseId(raw) {
  if (typeof raw !== 'string' || !/^[1-9]\d*$/.test(raw)) return null;
  const id = Number(raw);
  return Number.isSafeInteger(id) ? id : null;
}
function parsePage(raw) {
  if (raw === undefined) return 1;
  const page = parseId(raw);
  return page !== null && page <= 1000 ? page : null;
}
function createApp() {
  const express = require('express');
  const app = express();
  const students = [{ id: 1, ten: 'An' }, { id: 2, ten: 'Bình' }];
  app.get('/', (_req, res) => {
    res.type('text/plain').send('API học Express đang chạy.');
  });
  app.get('/sinh-vien', (req, res) => {
    const page = parsePage(req.query.trang);
    if (page === null) return res.status(400).json({ error: 'INVALID_PAGE' });
    const pageSize = 1;
    const start = (page - 1) * pageSize;
    res.json({ page, pageSize, total: students.length,
      items: students.slice(start, start + pageSize) });
  });
  app.get('/sinh-vien/:id', (req, res) => {
    const id = parseId(req.params.id);
    if (id === null) return res.status(400).json({ error: 'INVALID_ID' });
    const student = students.find(value => value.id === id);
    if (!student) return res.status(404).json({ error: 'NOT_FOUND' });
    res.json(student);
  });
  app.use((_req, res) => res.status(404).json({ error: 'ROUTE_NOT_FOUND' }));
  app.use((error, _req, res, _next) => {
    console.error('Lỗi xử lý:', error.code || error.name);
    res.status(500).json({ error: 'INTERNAL_ERROR' });
  });
  return app;
}
function start(app, report = console, markFailed = () => { process.exitCode = 1; }) {
  return app.listen(3000, '127.0.0.1', error => {
    if (error) {
      report.error('Không mở được cổng:', error.code || error.name);
      markFailed();
      return;
    }
    report.log('API: http://127.0.0.1:3000');
  });
}
if (require.main === module) start(createApp());
module.exports = { parseId, parsePage, createApp, start };
  1. parseId kiểm chuỗi số nguyên dương chuẩn trước khi Number, rồi kiểm Number.isSafeInteger. abc, 01, 0 và số quá lớn bị từ chối. Đây là quy tắc ID của bài, không phải mọi API phải có cùng định dạng.
  2. parsePage xử lý trường hợp không có query bằng mặc định 1; mảng/object hoặc giá trị không chuẩn bị từ chối. Giới hạn 1000 là quyết định minh họa, không tự suy ra lượng dữ liệu thật.
  3. createApp nạp Express và tạo danh sách cố định. Đường dẫn / trả text/plain; vì vậy client đọc text, không gọi response.json cho route này.
  4. GET /sinh-vien tính offset từ page và pageSize=1. slice chọn tối đa một hàng; total vẫn là tổng hai sinh viên. Trang 3 hợp lệ nên trả mảng rỗng. Phân trang mẫu không phải truy vấn database.
  5. GET /sinh-vien/:id kiểm ID rồi find bản ghi. Input không hợp lệ trả INVALID_ID/400; ID chuẩn không có trong dữ liệu trả NOT_FOUND/404. Không tạo tên giả để lấp bản ghi thiếu.
  6. Middleware 404 nằm sau route, nếu đặt trước nó sẽ chặn các route tiếp theo. Error middleware trả mã chung, không đưa stack hoặc lỗi nội bộ vào JSON; ghi mã/tên lỗi phía terminal để điều tra.
  7. start bind 127.0.0.1:3000 để chỉ thử trên máy local. Callback listen của Express 5 nhận lỗi mở cổng; phải kiểm error trước khi in URL. Khi cổng bận, mẫu đặt exitCode 1 thay vì in thành công giả.
  8. require.main tách chạy trực tiếp khỏi import kiểm thử. Chỉ import module để thử parseId không tự mở cổng hoặc cần nạp Express. Hàm start nhận report/markFailed để kiểm luồng thành công/lỗi mà không chiếm cổng thật.

Client kiểm status và JSON

Lưu thu-server.cjs rồi chạy trong terminal thứ hai tại thư mục thực hành. Client dùng fetch có sẵn trong Node và timeout 5 giây cho mỗi request; HTTP 400/404 không tự làm fetch reject, nên cần kiểm response.status và payload. assert thất bại làm chương trình báo lỗi, không chỉ in ra status rồi coi là đạt.

thu-server.cjs
'use strict';
const assert = require('node:assert/strict');
const base = 'http://127.0.0.1:3000';
async function main() {
  const cases = [
    ['/sinh-vien/1', 200, body => body.id === 1 && body.ten === 'An'],
    ['/sinh-vien/99', 404, body => body.error === 'NOT_FOUND'],
    ['/sinh-vien/abc', 400, body => body.error === 'INVALID_ID'],
    ['/sinh-vien?trang=2', 200, body => body.page === 2 && body.items[0].id === 2],
    ['/sinh-vien?trang=3', 200, body => body.items.length === 0],
    ['/sinh-vien?trang=0', 400, body => body.error === 'INVALID_PAGE'],
    ['/khong-co', 404, body => body.error === 'ROUTE_NOT_FOUND'],
  ];
  for (const [route, expected, check] of cases) {
    const response = await fetch(base + route, { signal: AbortSignal.timeout(5000) });
    assert.equal(response.status, expected);
    assert(check(await response.json()));
    console.log('Đạt:', route, response.status);
  }
}
main().catch(error => { console.error('Kiểm tra thất bại:', error.message); process.exitCode = 1; });

5. Lỗi thường gặp

  • MODULE_NOT_FOUND: kiểm đúng thư mục thực hành, npm ls express và package đã cài; không cài thêm vào website để chữa ví dụ.
  • require không tồn tại: giữ đuôi .cjs hoặc chuyển toàn bộ module theo cấu hình ESM có chủ đích, không trộn cú pháp ngẫu nhiên.
  • ERR_HTTP_HEADERS_SENT: tìm nhánh đã res.json nhưng vẫn tiếp tục gửi lần nữa; dùng return để dừng nhánh.
  • EADDRINUSE: cổng bận không đồng nghĩa app mới chạy; kiểm callback lỗi, chọn cổng thử thống nhất với client.
  • Nhầm params/query: /sinh-vien/2 và /sinh-vien?trang=2 đi hai route khác nhau và trả hai hình dạng JSON khác nhau.
  • 404 mọi URL: kiểm method, đường dẫn và thứ tự middleware. Không trả 200 kèm lỗi để che cấu hình route sai.

6. Bài tập ba mức

Dễ — hợp đồng request

Chạy bảy ca client, ghi status/payload mong đợi trước. Thêm ca /sinh-vien/01; giải thích khác nhau giữa input sai 400 và ID 99 không tồn tại 404. Kiểm đường gốc bằng response.text.

Vừa — phân trang và lỗi

Thử thiếu trang, trang 1/2/3, -1, abc, 1001 và query trang lặp. Kiểm input không chuẩn bị từ chối thay vì coercion thành số. Không suy kết quả query parser thật từ test double; ghi rõ môi trường Express đã cài khi thử HTTP.

Khó — kiểm khởi động

Viết test parseId/parsePage độc lập. Dùng app.listen double gọi callback lỗi EADDRINUSE; chứng minh không in URL và có báo thất bại. Sau đó thiết kế cách thêm POST/validation trong chương 24; chưa đưa auth hoặc MySQL vào bài cơ bản này chỉ để đủ stack.

7. Tóm tắt

Express app đăng ký route trước khi listen mở cổng. Params nhận ID trên đường dẫn; query điều khiển cách lấy danh sách; cả hai đều cần kiểm kiểu/giá trị. Response có status phù hợp và chỉ kết thúc một lần. Dữ liệu cố định trong RAM, thiếu auth, chưa có CRUD hoặc database nên đây là bài local. Tiếp tục sang chương 24, sau đó Node.js kết nối MySQL.
