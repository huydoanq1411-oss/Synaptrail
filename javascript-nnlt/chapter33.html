33 Unit Testing với Jest

Viết code tự động kiểm tra code khác — nền tảng để refactor tự tin mà không lo "vô tình làm hỏng cái gì đó".

terminal 
npm install --save-dev jest
toanHoc.js 
function cong(a, b) {
    return a + b;
}
function chia(a, b) {
    if (b === 0) throw new Error('Không thể chia cho 0');
    return a / b;
}
module.exports = { cong, chia };
toanHoc.test.js 
const { cong, chia } = require('./toanHoc');

test('cong 3 va 5 phai bang 8', () => {
    expect(cong(3, 5)).toBe(8);
});

describe('ham chia', () => {                          // describe nhóm các test liên quan
    test('chia 10 cho 2 phai bang 5', () => {
        expect(chia(10, 2)).toBe(5);
    });

    test('chia cho 0 phai nem ra loi', () => {
        expect(() => chia(10, 0)).toThrow('Không thể chia cho 0');
    });
});

// Chạy: npx jest
MatcherCông dụng
toBe(x)So sánh giá trị nguyên thủy (số, chuỗi, boolean) chính xác
toEqual(x)So sánh NỘI DUNG object/array (không cần cùng tham chiếu)
toThrow()Kiểm tra hàm có ném ra lỗi không
toBeNull() / toBeUndefined()Kiểm tra giá trị null/undefined
Mẹo
Nguyên tắc AAA khi viết test: Arrange (chuẩn bị dữ liệu đầu vào) → Act (gọi hàm cần test) → Assert (kiểm tra kết quả đúng như mong đợi) — cấu trúc này giúp test luôn rõ ràng, dễ đọc dù logic phức tạp tới đâu.
Ghi chú — Vitest
Jest vẫn cực kỳ phổ biến và là kiến thức nền tảng bắt buộc phải biết — cú pháp test(), describe(), các matcher expect() gần như giống hệt nhau giữa các framework. Tuy nhiên, với dự án mới năm 2026 (đặc biệt nếu dùng Vite, Nuxt, SvelteKit...), Vitest đang là lựa chọn mặc định được khuyến nghị nhờ tốc độ chạy test nhanh hơn đáng kể và hỗ trợ ES Module tốt hơn. Tin vui: code test viết cho Jest ở trên gần như chạy được ngay với Vitest chỉ sau một vài chỉnh sửa nhỏ về cú pháp import.

📌 Tổng kết chương 36

Jest cung cấp test()/describe() để tổ chức test, và các matcher (toBe/toEqual/toThrow) để kiểm tra kết quả — viết unit test giúp phát hiện lỗi sớm và tự tin refactor code sau này.
