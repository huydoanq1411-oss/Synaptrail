Chương 31 — Web Workers — Đa luồng trong trình duyệt

JavaScript vốn đơn luồng (single-threaded) — Web Worker cho phép chạy code nặng ở "luồng nền" mà không làm đứng giao diện.

Vấn đề: tác vụ nặng làm "đứng hình" giao diện

van_de_khong_worker.js 
function tinhToanNang() {
    let tong = 0;
    for (let i = 0; i < 10_000_000_000; i++) { tong += i; }   // vòng lặp CỰC LỚN
    return tong;
}
tinhToanNang();
// Trong lúc chạy đoạn này, TOÀN BỘ trang bị "đứng hình" -
// không click được nút, không cuộn được trang - vì JS chỉ có 1 luồng chính
worker.js (file riêng) 
// File worker.js - chạy trên LUỒNG RIÊNG, tách biệt hoàn toàn khỏi giao diện
self.onmessage = (event) => {
    const { soBatDau, soKetThuc } = event.data;
    let tong = 0;
    for (let i = soBatDau; i < soKetThuc; i++) { tong += i; }
    self.postMessage(tong);          // gửi kết quả VỀ luồng chính khi xong
};
main.js 
const worker = new Worker('worker.js');

worker.postMessage({ soBatDau: 0, soKetThuc: 10_000_000_000 });   // gửi việc CHO worker

worker.onmessage = (event) => {
    console.log('Kết quả:', event.data);      // nhận kết quả, giao diện KHÔNG hề bị đứng lúc tính toán
};
Quan trọng
Web Worker KHÔNG truy cập được DOM trực tiếp (không thể document.getElementById(...)) — chỉ giao tiếp với luồng chính qua postMessage()/onmessage. Phù hợp cho tính toán thuần túy (xử lý ảnh, phân tích dữ liệu lớn, mã hóa...), không phù hợp thao tác giao diện.

📌 Tổng kết chương 34

Web Worker chạy JS trên luồng nền riêng biệt, tránh làm "đứng" giao diện khi xử lý tác vụ nặng — giao tiếp với luồng chính qua postMessage(), không truy cập được DOM trực tiếp.
