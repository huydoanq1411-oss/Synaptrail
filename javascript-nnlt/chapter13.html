Chương 13 — Callback & Callback Hell

Cách xử lý bất đồng bộ nguyên thủy nhất của JS — và vấn đề nổi tiếng khi lạm dụng nó.

callback.js 
function taiDuLieu(callback) {
    setTimeout(() => {                    // setTimeout mô phỏng thao tác bất đồng bộ (gọi API...)
        callback("Dữ liệu đã tải xong");
    }, 1000);
}

taiDuLieu((ketQua) => {
    console.log(ketQua);   // "Dữ liệu đã tải xong" - in ra SAU 1 giây
});
console.log("Dòng này chạy TRƯỚC callback ở trên!");   // JS không "chờ" callback

Callback Hell — vấn đề khi lồng nhiều callback

callback_hell.js 
taiDuLieu((sv) => {
    taiDiem(sv, (diem) => {
        taiXepLoai(diem, (xepLoai) => {
            console.log(xepLoai);
            // càng nhiều bước bất đồng bộ nối tiếp -> code càng "thụt" sâu, khó đọc, khó bảo trì
        });
    });
});
Vấn đề — Callback Hell
Khi có nhiều thao tác bất đồng bộ phụ thuộc lẫn nhau, lồng callback tạo ra code hình "kim tự tháp ngược" rất khó đọc và debug — đây chính là lý do Promise (chương 14) ra đời.

📌 Tổng kết chương 13

Callback là hàm truyền vào để gọi lại sau khi thao tác bất đồng bộ hoàn thành. Lồng nhiều callback gây ra "Callback Hell" — vấn đề mà Promise được thiết kế để giải quyết.
