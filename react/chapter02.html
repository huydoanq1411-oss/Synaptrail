Chương 2 — Props — Truyền Dữ Liệu Giữa Component

Biến component tĩnh thành khối UI thực sự tái sử dụng được — dựng lại chính xác 6 card khóa học ở trang chủ chỉ bằng MỘT component duy nhất.

Giới thiệu

Component ThongTinKhoaHoc ở Bài 1 có một vấn đề lớn: dữ liệu khóa học được viết cứng ngay bên trong hàm. Muốn hiển thị 6 khóa học khác nhau (như trang chủ Full Stack Blueprint), bạn sẽ phải copy-paste component đó 6 lần, mỗi lần sửa một chút — đúng vấn đề mà HTML/CSS thuần từng gặp phải trước khi có BEM và component hóa.

Props (viết tắt của "properties") giải quyết vấn đề này: cho phép component cha truyền dữ liệu xuống component con, biến một component thành "khuôn mẫu" dùng lại được với dữ liệu khác nhau mỗi lần — đúng tinh thần Class ở Bài 17 chương JavaScript, nhưng áp dụng cho component giao diện.

🎯 Mục tiêu sau bài học

Tự truyền và nhận props giữa component cha-con, và dựng được một danh sách component lặp lại từ mảng dữ liệu bằng .map().

Kiến thức lý thuyết

2.1. Truyền props — giống thuộc tính HTML

truyền props 
<TheKhoaHoc ten="React.js" icon="⚛️" soBaiHoc={20} />
// ten, icon, soBaiHoc là các props — viết y hệt thuộc tính HTML
// giá trị chuỗi dùng dấu nháy, giá trị JS khác (số, biến...) dùng { }

2.2. Nhận props — tham số của component

Mọi props được gộp thành một object duy nhất, truyền vào component như tham số đầu tiên:

nhận props (cách đầy đủ) 
function TheKhoaHoc(props) {
  return <h3>{props.ten} — {props.soBaiHoc} bài</h3>;
}

Nhớ lại destructuring (Bài 7, chương JavaScript) — cách viết phổ biến hơn hẳn trong thực tế:

nhận props (destructuring — khuyến khích) 
function TheKhoaHoc({ ten, soBaiHoc }) {
  return <h3>{ten} — {soBaiHoc} bài</h3>;
}

2.3. Props chỉ đọc (read-only)

Quy tắc bất di bất dịch của React: component con không bao giờ được sửa trực tiếp props nhận vào (props.ten = "..." là sai). Props chỉ chảy theo một chiều: từ cha xuống con — giống hệt cách bạn không nên sửa trực tiếp tham số truyền vào một hàm thông thường (Bài 5).

2.4. Render danh sách component từ mảng dữ liệu

Kết hợp .map() (Bài 4, chương JavaScript) để biến một mảng dữ liệu thành nhiều component:

render danh sách 
const danhSachKhoaHoc = [
  { id: 1, ten: "HTML & CSS", icon: "🧱" },
  { id: 2, ten: "JavaScript", icon: "⚡" }
];

function DanhSach() {
  return (
    <div>
      {danhSachKhoaHoc.map(kh => (
        <TheKhoaHoc key={kh.id} ten={kh.ten} icon={kh.icon} />
      ))}
    </div>
  );
}

Prop key là bắt buộc khi render danh sách — giúp React nhận diện chính xác phần tử nào trong danh sách, tối ưu việc cập nhật lại khi dữ liệu thay đổi. Luôn dùng một id ổn định (không dùng chỉ số mảng nếu danh sách có thể thay đổi thứ tự — đúng bài học từ Bài 18 chương JavaScript).

Ví dụ minh họa

Hãy dựng lại chính xác grid 6 card khóa học ở trang chủ Full Stack Blueprint, nhưng lần này chỉ cần một component TheKhoaHoc duy nhất, được gọi lại 6 lần với dữ liệu khác nhau thông qua props — đúng nguyên lý component hóa cốt lõi của React.

Code mẫu

props.html 📋 Copy 
<div id="root"></div>

<script src="https://unpkg.com/react@19/umd/react.development.js"></script>
<script src="https://unpkg.com/react-dom@19/umd/react-dom.development.js"></script>
<script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>

<script type="text/babel">
  // Component CON — nhận props, không biết gì về dữ liệu thật sự đến từ đâu
  function TheKhoaHoc({ ten, icon, soBaiHoc }) {
    return (
      <div className="course-card">
        <span>{icon}</span>
        <h3>{ten}</h3>
        <p>{soBaiHoc} bài học</p>
      </div>
    );
  }

  // Dữ liệu — giống hệt mảng object đã dùng ở Bài 6, 10 chương JavaScript
  const danhSachKhoaHoc = [
    { id: 1, ten: "HTML & CSS", icon: "🧱", soBaiHoc: 11 },
    { id: 2, ten: "JavaScript", icon: "⚡", soBaiHoc: 19 },
    { id: 3, ten: "React.js", icon: "⚛️", soBaiHoc: 26 }
  ];

  // Component CHA — chứa dữ liệu, "rót" xuống từng component con qua props
  function TrangChu() {
    return (
      <div className="course-grid">
        {danhSachKhoaHoc.map(kh => (
          <TheKhoaHoc
            key={kh.id}
            ten={kh.ten}
            icon={kh.icon}
            soBaiHoc={kh.soBaiHoc}
          />
        ))}
      </div>
    );
  }

  const root = ReactDOM.createRoot(document.getElementById("root"));
  root.render(<TrangChu />);
</script>

Giải thích code

  • function TheKhoaHoc({ ten, icon, soBaiHoc }) { } — component con hoàn toàn "vô tri" về nguồn gốc dữ liệu, chỉ biết nó sẽ nhận được 3 props này và hiển thị ra — đây chính là tính tái sử dụng cốt lõi.
  • danhSachKhoaHoc.map(kh => (...)) — vòng lặp qua từng object trong mảng (Bài 4), mỗi lần tạo ra một phần tử <TheKhoaHoc /> mới với props tương ứng từ object đó.
  • key={kh.id} — dùng id ổn định của từng khóa học (không phải chỉ số mảng), giúp React theo dõi đúng từng component khi danh sách thay đổi sau này.
  • ten={kh.ten} — "rót" giá trị cụ thể từ object kh vào prop ten của component con; mỗi lần lặp, giá trị khác nhau, nhưng logic hiển thị bên trong TheKhoaHoc chỉ cần viết đúng một lần.
  • function TrangChu() { } — component cha đóng vai trò "điều phối": giữ dữ liệu, quyết định gọi component con bao nhiêu lần với props gì, còn phần hiển thị chi tiết giao lại hoàn toàn cho TheKhoaHoc.

Lỗi thường gặp

Nhấp vào từng mục để xem chi tiết lỗi và cách khắc phục:

Cố sửa trực tiếp props

Viết props.ten = "Tên mới"; bên trong component con — React sẽ báo lỗi hoặc bỏ qua thay đổi, vì props được coi là bất biến (immutable) từ góc nhìn của component con.

✅ Cách khắc phục: nếu cần dữ liệu thay đổi được, đó là dấu hiệu cần dùng state (Bài 3) thay vì props.

Quên prop key khi render danh sách

Viết .map(kh => <TheKhoaHoc ten={kh.ten} />) (thiếu key) — React vẫn hiển thị được nhưng cảnh báo trong console Warning: Each child in a list should have a unique "key" prop, và có thể gây lỗi hiển thị khó lường khi danh sách thay đổi.

✅ Cách khắc phục: luôn thêm key (dùng id ổn định) cho mọi phần tử được tạo ra từ .map().

Dùng chỉ số mảng (index) làm key

Viết .map((kh, index) => <TheKhoaHoc key={index} />) — hoạt động được với danh sách tĩnh, nhưng gây lỗi hiển thị khó lường nếu danh sách có thể thêm/xóa/sắp xếp lại — đúng bài học "id thay vì index" từ Bài 18 chương JavaScript.

✅ Cách khắc phục: luôn ưu tiên id thật của dữ liệu (như kh.id) làm key, chỉ dùng index khi chắc chắn danh sách hoàn toàn tĩnh, không bao giờ thay đổi.

Quên dấu ngoặc nhọn khi truyền props không phải chuỗi

Viết <TheKhoaHoc soBaiHoc="11" /> khi muốn truyền số 11 — nếu dùng dấu nháy, giá trị thực chất là chuỗi "11", không phải số, có thể gây lỗi khi component con thực hiện phép tính trên prop này.

✅ Cách khắc phục: giá trị không phải chuỗi (số, boolean, biến, object...) luôn cần bọc trong { }: soBaiHoc={11}.

⚠️ Cảnh báo quan trọng

Prop key là đặc biệt — React sử dụng nội bộ để theo dõi danh sách, component con không nhận được nó như một prop thông thường (không thể truy cập props.key bên trong component). Nếu cần giá trị đó bên trong component, phải truyền thêm một prop khác riêng biệt (như id={kh.id}).

Best Practices

  • Luôn destructuring props ngay trong tham số component ({ ten, icon }) thay vì dùng props.ten lặp lại nhiều lần.
  • Không bao giờ sửa trực tiếp props — coi chúng như tham số hàm chỉ đọc.
  • Luôn thêm key ổn định (id thật) khi render danh sách bằng .map().
  • Bọc mọi giá trị không phải chuỗi trong { } khi truyền props.
  • Giữ component con càng "vô tri" càng tốt — chỉ nhận props và hiển thị, không tự ý biết về nguồn gốc dữ liệu.

Tip & Note

💡 Tip

Với React Developer Tools (đã nhắc ở Bài 1), chọn một component trong tab Components sẽ hiện đầy đủ props nó đang nhận ở panel bên phải — cách nhanh nhất để debug khi nghi ngờ component không nhận đúng dữ liệu.

📌 Note

Props có một dạng đặc biệt tên children — tự động chứa mọi thứ nằm giữa thẻ mở và đóng của component, ví dụ <Card>Nội dung ở đây</Card>. Đây là kỹ thuật hữu ích để tạo component "bao bọc" linh hoạt, sẽ được dùng nhiều hơn ở các bài về layout sau này.

Bài tập

BÀI 1

Viết component NutBam nhận props nhan (nhãn nút) và mau (màu nền), hiển thị một nút với style tương ứng. Gọi lại component này 3 lần với 3 màu khác nhau.

BÀI 2

BÀI 3

Giải thích bằng lời: vì sao React coi việc sửa trực tiếp props bên trong component con là sai nguyên tắc, dù về mặt kỹ thuật code đôi khi vẫn "chạy được"?

📖 Đáp án bài tập 3 (gợi ý)

Nếu component con được phép sửa props, dữ liệu sẽ "chảy ngược" từ con lên cha một cách không kiểm soát — component cha (nơi thực sự sở hữu dữ liệu gốc) sẽ không còn biết chắc giá trị hiện tại là gì, vì bất kỳ component con nào cũng có thể âm thầm thay đổi nó. Nguyên tắc luồng dữ liệu một chiều giúp code React luôn dễ dự đoán: nhìn vào component cha là biết chắc dữ liệu đến từ đâu và thay đổi ra sao.

📌 Tổng kết chương 2

  • Props truyền dữ liệu từ component cha xuống con, theo một chiều duy nhất, chỉ đọc.
  • Nhận props qua destructuring trong tham số component, cách viết phổ biến nhất.
  • Kết hợp .map() + props để render danh sách component từ mảng dữ liệu.
  • Prop key bắt buộc khi render danh sách, nên dùng id ổn định thay vì chỉ số mảng.

Qua bài học này, bạn đã nắm được:

Với props, bạn đã biết cách "truyền" dữ liệu vào component. Nhưng nếu dữ liệu cần tự thay đổi theo thời gian (như số lượt click, nội dung ô input) mà không có component cha nào truyền vào? Ở Bài 3, bạn sẽ học State & useState — cách cho component "trí nhớ" của riêng nó.
