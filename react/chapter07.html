useEffect — Side Effects & Vòng đời Component

useEffect chạy mã có tác dụng phụ (gọi API, timer, đăng ký sự kiện) sau khi component render.

Làm quiz ở trang riêng

useEffect chạy mã có tác dụng phụ (gọi API, timer, đăng ký sự kiện) sau khi component render.

Cú pháp và mảng phụ thuộc

Effect.jsx 
import { useEffect, useState } from 'react';

function DongHo() {
  const [giay, setGiay] = useState(0);

  useEffect(() => {
    const id = setInterval(() => setGiay(g => g + 1), 1000);
    return () => clearInterval(id);   // dọn dẹp khi unmount
  }, []);                              // [] = chỉ chạy 1 lần sau lần render đầu

  return <p>Đã chạy {giay} giây</p>;
}
Mảng phụ thuộcEffect chạy khi nào
Không truyềnSau mỗi lần render
[]Một lần sau lần render đầu tiên
[a, b]Lần đầu và mỗi khi a hoặc b đổi

Hàm dọn dẹp (cleanup)

Giá trị trả về của effect là hàm dọn dẹp. React gọi nó trước khi chạy lại effect và khi component bị gỡ khỏi màn hình, để tránh rò rỉ bộ nhớ (timer, listener, kết nối).

📌 Lưu ý
Trong chế độ StrictMode ở môi trường phát triển, React cố ý chạy effect hai lần để phát hiện lỗi thiếu cleanup. Đó là hành vi bình thường, không phải bug.
💡 Mẹo
Không phải mọi thứ đều cần effect. Tính toán từ props/state hoặc xử lý sự kiện click nên viết trực tiếp trong render hoặc trong hàm xử lý, không dùng effect.

📌 Tổng kết chương 7

useEffect đồng bộ component với thế giới bên ngoài. Kiểm soát thời điểm chạy bằng mảng phụ thuộc và luôn dọn dẹp timer/listener bằng hàm cleanup.
