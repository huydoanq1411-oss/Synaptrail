Hashing & Bảng băm

Băm nhanh khi phân bố và tải phù hợp; cách dò và quy tắc xóa phải nhất quán, không hứa O(1) trong mọi tình huống.

Biên soạn theo tài liệu Cấu trúc dữ liệu và giải thuật — ThS. Bùi Văn Thượng, UTH. Đối chiếu mục 6.1, 6.2, 6.3. Nguồn và mục lục đối chiếu.

Mục tiêu

  • Phân biệt hàm băm, địa chỉ và đụng độ.
  • So sánh nối chuỗi, hợp nhất và ba phương pháp dò.
  • Cài thêm/tìm/xóa có tombstone và băm lại.

Vấn đề thực tế

Tra cứu mã sinh viên cần nhanh nhưng không thể cấp một ô cho mọi mã có thể có; nhiều khóa phải chia sẻ địa chỉ gốc.

Lý thuyết nền

Khái niệm và phép toán

Hash table (bảng băm) dùng hash function (hàm băm) ánh xạ khóa vào m ô. Collision (đụng độ) là hai khóa khác nhau có cùng địa chỉ. Hệ số tải α=n/m; cần khởi tạo, kiểm rỗng, đếm, tìm, thêm/cập nhật, xóa, duyệt và rehash (băm lại) khi đổi kích thước. Duyệt ô không tự cho thứ tự khóa tăng. Với phân bố phù hợp và tải được kiểm soát, tra cứu có kỳ vọng O(1); xấu nhất vẫn O(n).

Bốn cách xây hàm băm

  • Bảng tra: miền chữ a…z ánh xạ 0…25 khi chỉ nhận đúng 26 ký tự đó.
  • Chia: h(k)=k mod m; chọn m phù hợp phân bố khóa. Chuẩn hóa phần dư âm về 0…m−1.
  • Nhân: h(k)=floor(m·frac(kA)), 0<A<1; frac là phần lẻ. Công thức toán học cần chú ý làm tròn số thực khi cài.
  • Universal hashing (băm phổ quát): chọn ngẫu nhiên một hàm từ họ H; với mỗi cặp khóa phân biệt, xác suất đụng độ qua lựa chọn hàm ≤1/m. Xác suất không phải một thuộc tính của từng hàm cố định. Ví dụ họ h(a,b,k)=((ak+b) mod p) mod m cho khóa nguyên trong 0…p−1, p nguyên tố, a chọn 1…p−1 và b chọn 0…p−1.

Xử lý đụng độ

  • Separate chaining (kết nối trực tiếp): mỗi ô là đầu một danh sách khóa cùng địa chỉ; tìm/thêm/xóa trong chuỗi, chi phí phụ thuộc chiều dài chuỗi.
  • Coalesced hashing (kết nối hợp nhất): các bản ghi nằm trong cùng mảng, trường next lưu chỉ số ô kế tiếp. Ví dụ m=5, khóa 2 và 7 cùng ô 2; đặt 7 ở ô trống 4 và cho next[2]=4. Tìm theo chuỗi chỉ số; xóa phải nối lại và bảo toàn điểm bắt đầu của các chuỗi.
  • Linear probing (dò tuần tự): (h(k)+i) mod m; dễ tạo cụm liên tiếp.
  • Quadratic probing (dò bậc hai): (h(k)+i²) mod m; không mặc định ghé mọi ô. m=8 cho bình phương mod 8 chỉ có 0,1,4. Cần chọn kích thước, tải và công thức phù hợp.
  • Double hashing (băm kép): (h₁(k)+i·h₂(k)) mod m. Bước phải khác 0 và nguyên tố cùng nhau với m để đi đủ ô; m nguyên tố cùng 1≤h₂<m là một lựa chọn.

Dò luôn giới hạn tối đa m lượt. Xóa trong open addressing (địa chỉ mở) phải đánh dấu tombstone (ô đã xóa), không biến ngay thành ô chưa từng dùng; tìm kiếm phải đi tiếp qua tombstone. Bản dưới cài tập khóa số nguyên an toàn bằng dò tuần tự, tách EMPTY/DELETED khỏi giá trị khóa. Không phải hàm băm mật mã, không dùng bảo vệ mật khẩu.

Ví dụ có thể chạy

Lưu thành chapter15.cjs rồi chạy node chapter15.cjs. Các số trong ví dụ nằm trong miền nguyên an toàn, trừ phép chia biểu thức được giải thích riêng.

chapter15.cjs · JavaScript
class HashSet {
   constructor(m = 11) {
     if (!Number.isInteger(m) || m < 1) throw new RangeError('Kích thước sai');
     this.empty = Symbol('empty'); this.deleted = Symbol('deleted');
     this.slots = Array(m).fill(this.empty); this.size = 0;
   }
   hash(key) {
     if (!Number.isSafeInteger(key)) throw new TypeError('Khóa phải là số nguyên an toàn');
     return ((key % this.slots.length) + this.slots.length) % this.slots.length;
   }
   find(key) {
     const m = this.slots.length, start = this.hash(key);
     for (let i = 0; i < m; i++) {
       const pos = (start + i) % m;
       if (this.slots[pos] === this.empty) return -1;
       if (this.slots[pos] === key) return pos;
     }
     return -1;
   }
   add(key) {
     const start = this.hash(key);
     if (this.find(key) !== -1) return false;
     for (let i = 0; i < this.slots.length; i++) {
       const pos = (start + i) % this.slots.length;
       if (this.slots[pos] === this.empty || this.slots[pos] === this.deleted) {
         this.slots[pos] = key; this.size++; return true;
       }
     }
     throw new RangeError('Bảng đầy; cần rehash');
   }
   remove(key) {
     const pos = this.find(key); if (pos < 0) return false;
     this.slots[pos] = this.deleted; this.size--; return true;
   }
   values() { return this.slots.filter(x => x !== this.empty && x !== this.deleted); }
   rehash(m) {
     const next = new HashSet(m);
     for (const key of this.values()) next.add(key);
     this.slots = next.slots; this.empty = next.empty; this.deleted = next.deleted;
   }
 }
 const h = new HashSet(10);
 for (const key of [32,53,22,92,17,34,24,37,56]) h.add(key);
 h.remove(22);
 console.log(h.find(92) !== -1, h.size); // true 8
 h.rehash(23);
 console.log(h.values().length); // 8

Giải thích các đoạn quan trọng

  1. Hai Symbol phân biệt ô chưa dùng và đã xóa; các khóa như −1 vẫn hợp lệ.
  2. hash kiểm miền khóa và chuẩn hóa số dư. find dừng ở EMPTY, bỏ qua DELETED và không lặp quá m ô.
  3. add kiểm khóa trùng trước khi dùng lại tombstone; remove giữ đường dò cho các khóa phía sau.
  4. rehash tạo bảng mới và thêm lại từng khóa theo kích thước mới; chỉ gán bảng mới sau khi xây thành công.
  5. Theo dãy ví dụ, 32 ở ô 2; 53 ở 3; 22 dò đến 4; 92 đến 5. Xóa 22 vẫn phải tìm được 92 ở phía sau.

Lỗi thường gặp

  • Dùng −1 làm ô rỗng khi −1 là khóa hợp lệ.
  • Tìm dừng ở ô đã xóa, làm mất dấu khóa phía sau.
  • Băm kép có bước 0 hoặc không nguyên tố cùng nhau với m.

Bài tập ba mức

Mức 1 — Cơ bản

Lập bảng dò tuần tự m=10 với 32,53,22,92,17,34,24,37,56; ghi từng lần đụng độ.

Mức 2 — Vận dụng

Thêm/tìm/xóa cùng bộ khóa bằng nối chuỗi; so sánh trạng thái sau xóa với tombstone.

Mức 3 — Nâng cao

Thiết kế bảng tra, hàm chia/nhân, họ phổ quát và băm kép; nêu miền khóa, tải, cách rehash và giới hạn lượt dò. Đây là bài tập bổ sung: chương 6 nguồn không có bài tập riêng.
