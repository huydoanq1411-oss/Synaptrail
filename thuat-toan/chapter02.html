Big O Notation

Luôn ghi đại lượng đếm, kích thước đầu vào và trường hợp đang xét; Big O là cận, không phải đồng hồ.

Biên soạn theo tài liệu Cấu trúc dữ liệu và giải thuật — ThS. Bùi Văn Thượng, UTH. Đối chiếu mục 1.3.3. Nguồn và mục lục đối chiếu.

Mục tiêu

  • Hiểu định nghĩa Big O.
  • Tách trường hợp đầu vào khỏi ký hiệu tiệm cận.

Vấn đề thực tế

Hai máy chạy cùng thuật toán có thời gian khác nhau; cần so sánh tốc độ tăng của số thao tác khi dữ liệu lớn hơn.

Lý thuyết nền

Big O là cận trên tiệm cận: T(n) thuộc O(g(n)) nếu tồn tại c > 0 và n₀ sao cho 0 ≤ T(n) ≤ c·g(n) với n ≥ n₀. Bỏ hằng số và số hạng bậc thấp khi xét tăng trưởng. Θ mô tả cận chặt hai phía, Ω là cận dưới.

Big O không tự mang nghĩa trường hợp xấu nhất. Hãy nêu đang phân tích best case (tốt nhất), worst case (xấu nhất) hay average case (trung bình). Trung bình cần giả thiết phân bố đầu vào.

Các lớp thường gặp theo tốc độ tăng: O(1), O(log n), O(n), O(n log n), O(n²), O(n³), O(2ⁿ), O(n!). Đây là mô hình tăng trưởng, không phải số giây hay số phép toán chính xác. Logarit khác cơ số chỉ khác hằng số.

Ví dụ có thể chạy

JavaScript, Node.js 22 trở lên; không dùng thư viện ngoài. Đây là bản chuyển thể cho website, không phải bản chép mã C/C++ bị dính dòng trong tài liệu Markdown. Lưu thành chapter02.cjs rồi chạy node chapter02.cjs. Các số trong ví dụ nằm trong miền nguyên an toàn, trừ phép chia biểu thức được giải thích riêng.

chapter02.cjs · JavaScript
function demSoSanh(a, x) {
   let dem = 0;
   for (const giaTri of a) {
     dem++;
     if (giaTri === x) return dem;
   }
   return dem;
 }
 console.log(demSoSanh([2, 4, 6, 8], 2)); // 1
 console.log(demSoSanh([2, 4, 6, 8], 9)); // 4

Giải thích các đoạn quan trọng

  1. dem bắt đầu bằng 0 và chỉ đếm phép so sánh khóa, không đếm mọi lệnh máy.
  2. Mỗi phần tử làm dem tăng một; return dừng khi trúng khóa.
  3. Đầu dãy cho 1 phép so sánh; không tìm thấy cho n phép: tốt nhất Θ(1), xấu nhất Θ(n).

Lỗi thường gặp

  • Gọi O(n) là đúng n giây hoặc đúng n lệnh.
  • Viết “Big O luôn là trường hợp xấu nhất”.

Bài tập ba mức

Mức 1 — Cơ bản

Rút gọn cận của 3n + 7.

Mức 2 — Vận dụng

So sánh n² và n log₂ n khi n tăng gấp đôi.

Mức 3 — Nâng cao

Nêu giả thiết để số lần so sánh tuyến tính trung bình khi tìm thành công là (n + 1)/2.
