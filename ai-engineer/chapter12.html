Tool Use (Function Calling) hoạt động ra sao?

tool_use_concept.py 
import anthropic

client = anthropic.Anthropic()  # đọc ANTHROPIC_API_KEY từ biến môi trường

def lay_thoi_tiet(thanh_pho):                # hàm THẬT mà chương trình của bạn định nghĩa
    # trong thực tế sẽ gọi API thời tiết thật, đây là dữ liệu giả lập
    du_lieu = {"Hà Nội": "28°C, nhiều mây", "TP.HCM": "32°C, nắng"}
    return du_lieu.get(thanh_pho, "Không có dữ liệu")

# Khai báo cho LLM biết "công cụ" này tồn tại và cách dùng nó
cong_cu = [{
    "name": "lay_thoi_tiet",
    "description": "Lấy thông tin thời tiết hiện tại của một thành phố",
    "input_schema": {
        "type": "object",
        "properties": {
            "thanh_pho": {"type": "string", "description": "Tên thành phố, VD: Hà Nội"}
        },
        "required": ["thanh_pho"]
    }
}]

response = client.messages.create(
    model="YOUR_CURRENT_CLAUDE_MODEL_ID",
    max_tokens=500,
    tools=cong_cu,
    messages=[{"role": "user", "content": "Hà Nội hôm nay thời tiết thế nào?"}]
)

# Nếu LLM quyết định cần gọi công cụ, response sẽ chứa yêu cầu gọi hàm
if response.stop_reason == "tool_use":
    for block in response.content:
        if block.type == "tool_use" and block.name == "lay_thoi_tiet":
            ket_qua = lay_thoi_tiet(block.input["thanh_pho"])   # CHƯƠNG TRÌNH thực thi hàm thật
            print(f"Kết quả từ tool: {ket_qua}")
            # Sau đó gửi kết quả này NGƯỢC LẠI cho LLM để nó tạo câu trả lời cuối cùng bằng ngôn ngữ tự nhiên
Quan trọng
LLM KHÔNG tự thực thi hàm — nó chỉ quyết định "cần gọi hàm nào, với tham số gì" rồi trả về yêu cầu đó. Chương trình của bạn (code Python) mới là nơi THỰC SỰ chạy hàm, sau đó gửi kết quả về lại cho LLM để tạo câu trả lời cuối cùng.
Mẹo
Vòng lặp "suy nghĩ → hành động → quan sát" (thường gọi là ReAct pattern) có thể lặp NHIỀU LẦN trong một câu hỏi phức tạp — VD: agent tự gọi công cụ tìm kiếm, rồi gọi công cụ tính toán trên kết quả tìm được, trước khi trả lời cuối cùng.

Model Context Protocol (MCP) — chuẩn hóa việc kết nối tool

Ví dụ ở trên khai báo từng tool trực tiếp trong ứng dụng. MCP (Model Context Protocol) là một chuẩn mở client-server để ứng dụng kết nối với server cung cấp công cụ và ngữ cảnh theo giao thức chung. MCP giúp giảm phần tích hợp riêng lẻ, nhưng không tự làm mọi model/client tương thích: vẫn cần client, adapter và quyền truy cập phù hợp. Chuẩn được Anthropic công bố cuối năm 2024.

Ghi chú
Mức hỗ trợ và hệ sinh thái MCP thay đổi theo client/server. Trước khi dùng server bên thứ ba, kiểm tra nguồn phát hành, quyền được yêu cầu, cách xử lý secrets và dữ liệu gửi đi; chỉ bật tool cần thiết. MCP không thay thế xác thực, phân quyền hay kiểm tra kết quả ở ứng dụng.

Quy tắc an toàn cho tool

  • Kiểm tra tên tool, kiểu dữ liệu, phạm vi và quyền của người gọi ở phía ứng dụng; schema chỉ xác thực hình dạng, không chứng minh yêu cầu là hợp lệ.
  • Áp dụng quyền tối thiểu, giới hạn số vòng lặp/thời gian/chi phí và yêu cầu người dùng xác nhận trước thao tác không thể hoàn tác.
  • Coi kết quả từ web, tệp và MCP server là dữ liệu không đáng tin cậy; không thực thi lệnh hoặc truy vấn chỉ vì model yêu cầu.
  • Ghi lại tool được gọi và kết quả đã khử dữ liệu nhạy cảm để có thể kiểm tra/audit.
