Chương 17 — Multi-Agent Systems

Nhiều AI Agent chuyên biệt phối hợp với nhau để giải quyết bài toán phức tạp — thay vì một Agent "biết tuốt".

Tại sao cần nhiều Agent thay vì một Agent duy nhất?

Một Agent với quá nhiều công cụ (tool) và trách nhiệm dễ bị "quá tải" — khó chọn đúng công cụ, dễ nhầm lẫn ngữ cảnh. Chia nhỏ thành các Agent CHUYÊN BIỆT (giống chia Microservices đã học ở System Design) giúp mỗi Agent làm tốt MỘT việc.

multi_agent_concept.py 
# Kiến trúc: 1 Agent điều phối (Orchestrator) + nhiều Agent chuyên biệt
class AgentDieuPhoi:
    def __init__(self):
        self.agent_tim_kiem = AgentTimKiem()
        self.agent_tinh_toan = AgentTinhToan()
        self.agent_viet_bao_cao = AgentVietBaoCao()

    def xu_ly(self, yeu_cau):
        # Agent điều phối PHÂN TÍCH yêu cầu, quyết định gọi agent con nào
        if "tìm kiếm" in yeu_cau.lower():
            ket_qua = self.agent_tim_kiem.xu_ly(yeu_cau)
        elif "tính" in yeu_cau.lower():
            ket_qua = self.agent_tinh_toan.xu_ly(yeu_cau)
        # ... rồi có thể chuyển tiếp kết quả cho agent_viet_bao_cao để tổng hợp
        return ket_qua
Mô hìnhMô tả
Orchestrator-WorkerMột Agent điều phối chính, giao việc cho các Agent con chuyên biệt
Sequential (Tuần tự)Agent A xử lý xong, kết quả chuyển tiếp cho Agent B, rồi Agent C
Debate/ReviewNhiều Agent cùng giải bài toán độc lập, một Agent khác so sánh/chọn kết quả tốt nhất
Cảnh báo
Multi-Agent làm tăng chi phí (mỗi Agent = một lượt gọi LLM riêng) và độ trễ đáng kể — chỉ nên dùng khi bài toán THỰC SỰ cần chia nhỏ (quá phức tạp cho 1 Agent), không phải vì "nghe có vẻ hiện đại hơn".
Ghi chú — Framework thực tế
Trong thực tế, ít ai tự viết kiến trúc điều phối từ đầu như ví dụ minh họa trên — các framework phổ biến (LangGraph, CrewAI, Claude Agent SDK, OpenAI Agents SDK...) đã cung cấp sẵn cơ chế orchestrator, quản lý trạng thái và truyền dữ liệu giữa các agent. Ngoài ra, khi các Agent cần giao tiếp CHÉO giữa nhiều nhà cung cấp AI khác nhau (không chỉ trong một hệ thống), cộng đồng đang chuẩn hóa thêm giao thức A2A (Agent-to-Agent), đóng vai trò bổ sung cho MCP (chương 12) — MCP chuẩn hóa việc Agent gọi tool/dữ liệu, còn A2A chuẩn hóa việc Agent nói chuyện với Agent khác.

Chọn workflow trước khi chọn thêm agent

Nếu các bước và nhánh xử lý đã biết trước, workflow xác định thường dễ kiểm thử, rẻ và dễ audit hơn agent tự quyết định. Dùng nhiều agent khi có lợi ích đo được từ phân vai hoặc chạy song song; đặt giới hạn bước, thời gian và ngân sách, lưu trạng thái cần phục hồi, và xác định điểm dừng khi kết quả không hợp lệ. So sánh với một-agent baseline trên cùng bộ tác vụ trước khi mở rộng.
