01Prompt Engineering cơ bản

Kỹ năng viết prompt quyết định trực tiếp chất lượng câu trả lời của LLM — trước khi nói đến Agent hay công cụ, đây là kỹ năng nền phải nắm chắc.

▸ System Prompt — định hình "vai trò" của mô hình

System prompt là nơi bạn khai báo: mô hình đóng vai gì, phạm vi được trả lời, giọng văn, và cách xử lý khi câu hỏi ngoài phạm vi.

response = client.messages.create(
    model="YOUR_CURRENT_CLAUDE_MODEL_ID",
    max_tokens=1000,
    system="""Bạn là trợ lý hỗ trợ khách hàng của cửa hàng TechShop.
Chỉ trả lời các câu hỏi về sản phẩm, đơn hàng, và chính sách của TechShop.
Nếu khách hỏi ngoài phạm vi này, lịch sự từ chối và hướng dẫn liên hệ hotline.
Luôn trả lời ngắn gọn, thân thiện, bằng tiếng Việt.""",
    messages=[{"role": "user", "content": "Shop có bán laptop không?"}]
)

▸ 4 kỹ thuật prompt hiệu quả

Chỉ định định dạng đầu ra"Trả lời dưới dạng JSON với các trường: ten, gia" giúp dễ xử lý bằng code

💡 Mẹo Few-shot (cho vài ví dụ mẫu ngay trong prompt) thường cải thiện độ chính xác rõ rệt so với chỉ mô tả yêu cầu bằng lời — đặc biệt hữu ích khi cần LLM trả lời theo định dạng cố định, nhất quán.
📌 Tổng kết System prompt định hình nhiệm vụ và định dạng mong muốn, nhưng không phải ranh giới bảo mật. Dùng ví dụ và schema khi hữu ích; xác thực đầu ra trong code và đánh giá trên tác vụ thực tế vì hiệu quả khác nhau giữa model, prompt và dữ liệu.

02AI Agent & Tool Use

Bước tiến hóa tiếp theo sau chatbot: LLM không chỉ trả lời bằng văn bản mà còn có thể quyết định gọi hàm/công cụ để hành động.

▸ Chatbot thường vs AI Agent

Tiêu chíChatbot thông thườngAI Agent
Đầu raChỉ trả lời bằng văn bảnCó thể gọi hàm/công cụ để thực hiện hành động
Luồng xử lý1 lượt hỏi – 1 lượt đápLặp nhiều bước: suy nghĩ → hành động → quan sát → suy nghĩ tiếp (ReAct)
Ví dụ"Hà Nội là thủ đô Việt Nam"Tự gọi API thời tiết để trả lời "Hà Nội hôm nay bao nhiêu độ?"

▸ Tool Use (Function Calling) hoạt động ra sao?

def lay_thoi_tiet(thanh_pho):                # hàm THẬT do bạn định nghĩa
    du_lieu = {"Hà Nội": "28°C, nhiều mây", "TP.HCM": "32°C, nắng"}
    return du_lieu.get(thanh_pho, "Không có dữ liệu")

cong_cu = [{
    "name": "lay_thoi_tiet",
    "description": "Lấy thông tin thời tiết hiện tại của một thành phố",
    "input_schema": {
        "type": "object",
        "properties": {
            "thanh_pho": {"type": "string", "description": "Tên thành phố, VD: Hà Nội"}
        },
        "required": ["thanh_pho"]
    }
}]

response = client.messages.create(
    model="YOUR_CURRENT_CLAUDE_MODEL_ID", max_tokens=500,
    tools=cong_cu,
    messages=[{"role": "user", "content": "Hà Nội hôm nay thời tiết thế nào?"}]
)

if response.stop_reason == "tool_use":
    for block in response.content:
        if block.type == "tool_use" and block.name == "lay_thoi_tiet":
            ket_qua = lay_thoi_tiet(block.input["thanh_pho"])   # code của bạn CHẠY hàm thật
            # gửi ket_qua ngược lại cho LLM để nó soạn câu trả lời cuối cùng
⚠️ Quan trọng LLM không tự thực thi hàm — nó chỉ quyết định "cần gọi hàm nào, tham số gì" rồi trả yêu cầu đó về. Chương trình của bạn mới là nơi thực sự chạy hàm, sau đó gửi kết quả ngược lại để LLM tạo câu trả lời cuối cùng.

▸ Model Context Protocol (MCP) — chuẩn hoá việc kết nối tool

MCP là chuẩn client-server mở được Anthropic công bố cuối năm 2024, giúp chuẩn hóa cách ứng dụng kết nối với server cung cấp tool và context. Khả năng hỗ trợ tùy client, adapter và phiên bản; MCP không tự làm mọi model tương thích. Kiểm tra tài liệu chính thức, quyền, nguồn gốc server và chính sách dữ liệu trước khi kết nối.

📌 Tổng kết AI Agent mở rộng chatbot bằng khả năng "tool use": LLM quyết định cần công cụ nào, chương trình thực thi thật, rồi gửi kết quả ngược lại để LLM hoàn thiện câu trả lời. MCP là hạ tầng chuẩn giúp việc này mở rộng dễ dàng.

03Multi-Agent Systems

Nhiều AI Agent chuyên biệt phối hợp thay vì một Agent "biết tuốt" — giống tư duy Microservices trong System Design.

▸ Vì sao cần nhiều Agent?

Một Agent ôm quá nhiều tool/trách nhiệm dễ "quá tải": khó chọn đúng công cụ, dễ nhầm ngữ cảnh. Chia nhỏ thành các Agent chuyên biệt giúp mỗi Agent làm tốt một việc.

# Kiến trúc: 1 Agent điều phối (Orchestrator) + nhiều Agent chuyên biệt
class AgentDieuPhoi:
    def __init__(self):
        self.agent_tim_kiem = AgentTimKiem()
        self.agent_tinh_toan = AgentTinhToan()
        self.agent_viet_bao_cao = AgentVietBaoCao()

    def xu_ly(self, yeu_cau):
        if "tìm kiếm" in yeu_cau.lower():
            ket_qua = self.agent_tim_kiem.xu_ly(yeu_cau)
        elif "tính" in yeu_cau.lower():
            ket_qua = self.agent_tinh_toan.xu_ly(yeu_cau)
        return ket_qua
Mô hìnhMô tả
Orchestrator–WorkerMột Agent điều phối chính, giao việc cho các Agent con chuyên biệt
Sequential (Tuần tự)Agent A xử lý xong → chuyển kết quả cho B → rồi C
Debate / ReviewNhiều Agent giải độc lập, một Agent khác so sánh & chọn kết quả tốt nhất
⚠️ Cảnh báo Multi-Agent làm tăng chi phí (mỗi Agent = một lượt gọi LLM riêng) và độ trễ đáng kể — chỉ dùng khi bài toán thực sự cần chia nhỏ, không phải vì "nghe hiện đại hơn".

Các framework như LangGraph, CrewAI, Claude Agent SDK và OpenAI Agents SDK có cách tổ chức workflow/trạng thái khác nhau; đối chiếu tài liệu và thử trên yêu cầu của mình thay vì mặc định framework nào tốt nhất. A2A là một giao thức hướng tới tương tác agent-to-agent; đây không phải điều kiện để xây multi-agent, và nên đánh giá nhu cầu liên vận trước khi thêm một giao thức.

04Bản đồ công cụ AI đang thịnh hành

Một số ví dụ theo nhóm sản phẩm — framework agent, coding agent, tự động hóa và công cụ đa phương tiện. Tính năng, giá, quyền riêng tư và khả năng tích hợp đổi nhanh; hãy xác minh tại nguồn chính thức trước khi chọn.

▸ A. Framework xây dựng AI Agent

Claude Agent SDK Anthropic

SDK để xây agent theo hệ sinh thái Anthropic; kiểm tra khả năng model, môi trường chạy, quyền và điều khoản hiện hành.

LangGraph LangChain

Định nghĩa luồng xử lý dạng graph/state; phù hợp khi cần nhánh, checkpoint hoặc human-in-the-loop. Đối chiếu độ phức tạp với workflow thuần.

CrewAI

Framework tổ chức agent theo vai trò/nhiệm vụ; đánh giá cách quản lý trạng thái, tích hợp và quan sát theo phiên bản đang dùng.

OpenAI Agents SDK

SDK agent trong hệ sinh thái OpenAI; xác minh provider/model, handoff và tính năng tracing theo tài liệu hiện hành.

Google ADK

Framework agent của Google; xem xét khi cần tích hợp hệ sinh thái Google, đồng thời kiểm tra khả năng triển khai và tương thích.

Microsoft Agent Framework

Framework thuộc hệ sinh thái Microsoft; kiểm tra trạng thái phát hành, hỗ trợ ngôn ngữ và lộ trình migration trước khi dùng.

Các lựa chọn khác gồm Mastra, Vercel AI SDK, Pydantic AI, LlamaIndex Workflows và n8n. So sánh theo ngôn ngữ, triển khai, state persistence, kiểm soát quyền, tracing, chi phí và khả năng thay thế provider; model routing chỉ hữu ích nếu cải thiện chất lượng/chi phí trên benchmark nội bộ.

▸ C. Tự động hoá không cần code (No-code Agent)

n8n, Make, Zapier — dựng workflow AI bằng kéo-thả, kết nối agent với hàng trăm ứng dụng khác mà không cần viết code, phù hợp cho automation nội bộ doanh nghiệp hoặc cá nhân không rành lập trình.

▸ D. Công cụ sáng tạo đa phương tiện (ảnh / video / thiết kế)

Runway, Kling, Veo, Luma Ray

Các mô hình text-to-video/ image-to-video hàng đầu, chất lượng điện ảnh, hỗ trợ chuyển động camera phức tạp.

Leonardo, Adobe Firefly

Sinh ảnh có kiểm soát cao, huấn luyện model riêng, render chữ trong ảnh tốt.

Krea, Freepik AI

Nền tảng tổng hợp nhiều model ảnh/video/3D, workflow dạng node, phù hợp pipeline lặp lại.

Canva AI, CapCut

Thiết kế & dựng video AI cho người không chuyên, tích hợp sẵn trong công cụ quen thuộc.
