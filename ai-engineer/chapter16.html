Chương 16 — Vector Database chuyên sâu

Ở chương 10, RAG dùng TF-IDF đơn giản để minh họa ý tưởng — thực tế production dùng vector database chuyên dụng với embedding thật.

Embedding thật vs TF-IDF minh họa

embedding_that.py 
# pip install voyageai
import voyageai

client = voyageai.Client()   # đọc API key từ biến môi trường VOYAGE_API_KEY

def lay_embedding(van_ban):
    # Voyage AI là nhà cung cấp embedding được Anthropic khuyến nghị dùng kèm Claude
    # Ý tưởng: văn bản -> vector số thực nhiều chiều (thường 256-2048 chiều tùy model)
    ket_qua = client.embed([van_ban], model="YOUR_CURRENT_EMBEDDING_MODEL_ID", input_type="document")
    return ket_qua.embeddings[0]   # VD: [0.023, -0.11, 0.045, ...] hàng trăm số
Ghi chú
Ngoài Voyage AI, các nhà cung cấp khác cũng có model embedding riêng (VD: OpenAI text-embedding-3) — về bản chất đều làm cùng một việc: biến văn bản thành vector số để so sánh độ tương đồng ngữ nghĩa.

Vector Database — lưu trữ và tìm kiếm hàng triệu vector

Vector DBĐặc điểm
PineconeDịch vụ đám mây (managed), dễ dùng, không cần tự quản lý hạ tầng
ChromaMã nguồn mở, chạy được local, phù hợp dự án nhỏ/prototype
FAISSThư viện của Meta, cực nhanh, chạy hoàn toàn trong bộ nhớ (không phải "database" đầy đủ)
chroma_demo.py 
# pip install chromadb
import chromadb

client = chromadb.Client()
collection = client.create_collection("tai_lieu_cong_ty")

collection.add(
    documents=["Chính sách bảo hành 12 tháng.", "Đổi trả trong 7 ngày."],
    ids=["doc1", "doc2"]
)

ket_qua = collection.query(
    query_texts=["Tôi muốn trả hàng"],
    n_results=1
)
print(ket_qua['documents'])   # tự động embedding + tìm kiếm gần nhất, không cần tự viết cosine similarity
Quan trọng — HNSW Index
Vector database chuyên dụng dùng thuật toán index như HNSW (Hierarchical Navigable Small World) để tìm kiếm gần đúng (Approximate Nearest Neighbor) cực nhanh trên hàng triệu vector — đánh đổi độ chính xác tuyệt đối lấy tốc độ, khác hẳn việc so sánh cosine similarity tuần tự (đã minh họa ở chương 10) chỉ khả thi với vài nghìn bản ghi.

Vận hành index và thay đổi embedding model

Dimension, chuẩn hóa vector và metric phải tương thích với index. Khi đổi embedding model, không trộn vector cũ và mới trong cùng không gian; tạo index/namespace mới, re-embed, đánh giá truy vấn, rồi chuyển traffic có kiểm soát. Lưu ID tài liệu và phiên bản nguồn để cập nhật/xóa chính xác; lọc quyền truy cập ở tầng truy vấn. Với câu hỏi, dùng chế độ input dành cho query nếu nhà cung cấp yêu cầu. Tên model trong ví dụ là placeholder, cần thay bằng ID hiện được hỗ trợ.
