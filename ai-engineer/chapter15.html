Chương 15 — Triển khai Chatbot lên Production

Đưa chatbot từ script chạy console sang ứng dụng thực tế phục vụ người dùng thật — những điều cần bổ sung.

Từ console script đến API backend

chatbot_api_flask.py 
# pip install flask
from flask import Flask, request, jsonify
import anthropic

app = Flask(__name__)
client = anthropic.Anthropic()   # API key đọc từ biến môi trường ANTHROPIC_API_KEY

# Lưu lịch sử theo từng phiên (session) người dùng, KHÔNG dùng biến toàn cục chung
lich_su_theo_session = {}

@app.route("/chat", methods=["POST"])
def chat_endpoint():
    du_lieu = request.get_json()
    session_id = du_lieu.get("session_id")
    tin_nhan = du_lieu.get("message")

    if session_id not in lich_su_theo_session:
        lich_su_theo_session[session_id] = []

    lich_su = lich_su_theo_session[session_id]
    lich_su.append({"role": "user", "content": tin_nhan})

    response = client.messages.create(
        model="YOUR_CURRENT_CLAUDE_MODEL_ID", max_tokens=500, messages=lich_su
    )
    tra_loi = response.content[0].text
    lich_su.append({"role": "assistant", "content": tra_loi})

    return jsonify({"reply": tra_loi})

if __name__ == "__main__":
    app.run(port=5000)
Ví dụ API này chưa phải production
Dictionary toàn cục chỉ tồn tại trong RAM, mất dữ liệu khi restart và không đồng bộ giữa nhiều worker; endpoint minh họa cũng chưa có xác thực hay kiểm tra đầu vào đầy đủ. Không triển khai nguyên trạng. Dùng kho lưu trữ phù hợp, gắn session với danh tính đã xác thực, phân quyền truy cập, giới hạn kích thước request và xóa dữ liệu theo chính sách.

Checklist trước khi đưa chatbot lên production

  • ✅ Lưu API key trong biến môi trường, KHÔNG hardcode trong source code
  • ✅ Quản lý lịch sử hội thoại theo TỪNG người dùng/phiên riêng biệt (không dùng biến toàn cục chung)
  • ✅ Giới hạn độ dài lịch sử hội thoại để kiểm soát chi phí API (VD: chỉ giữ 10 lượt gần nhất)
  • ✅ Xử lý lỗi khi API bị timeout, hết quota, hoặc trả về lỗi
  • ✅ Ghi log có kiểm soát, giảm thiểu/ẩn danh dữ liệu nhạy cảm và đặt thời hạn lưu trữ
  • ✅ Đặt rate limiting (giới hạn số request/phút mỗi người dùng) để tránh bị lạm dụng và tốn chi phí
  • ✅ Có phương án "leo thang" (escalation) chuyển cho nhân viên thật khi chatbot không xử lý được
  • ✅ Theo dõi latency, lỗi, token/chi phí, chất lượng và tỷ lệ chuyển người thật; cảnh báo theo ngưỡng
  • ✅ Có kiểm thử hồi quy, quy trình rollback model/prompt và kế hoạch xử lý sự cố
Cảnh báo — Quản lý chi phí
Không giới hạn độ dài lịch sử hội thoại là lỗi phổ biến khiến chi phí API tăng phi mã — mỗi lượt gọi gửi lại TOÀN BỘ lịch sử, cuộc trò chuyện càng dài, mỗi lượt tiếp theo càng tốn nhiều token hơn.
