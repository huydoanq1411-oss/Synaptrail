Clean Code

Nguyên tắc viết code dễ đọc, dễ hiểu, dễ bảo trì — kỹ năng phân biệt lập trình viên giỏi.

Nguyên tắc viết code dễ đọc, dễ hiểu, dễ bảo trì — kỹ năng phân biệt lập trình viên giỏi.

before_after.py 
# TRƯỚC - khó đọc
def f(x, y, z):
    if z == 1:
        return x * y * 0.9
    return x * y

# SAU - rõ ràng, tự giải thích
def tinh_tong_tien(don_gia, so_luong, co_giam_gia):
    THUE_SUAT_GIAM_GIA = 0.9
    tong = don_gia * so_luong
    if co_giam_gia:
        return tong * THUE_SUAT_GIAM_GIA
    return tong

Các nguyên tắc chính

  • Đặt tên rõ nghĩa: tinh_tong_tien tốt hơn f, so_luong_san_pham tốt hơn x.
  • Hàm nên làm một việc duy nhất (Single Responsibility) — nếu tên hàm có chữ "và" (ví dụ "luu_va_gui_email"), có thể nên tách thành 2 hàm.
  • Tránh magic number: dùng hằng số có tên (THUE_SUAT_GIAM_GIA) thay vì số "0.9" xuất hiện trực tiếp trong code.
  • Hàm ngắn gọn: nếu một hàm dài hơn 1 màn hình, cân nhắc tách nhỏ.
  • Tránh comment thừa: code rõ ràng tự nó đã "giải thích" — comment chỉ nên giải thích "tại sao", không lặp lại "cái gì".
Mẹo ghi nhớ
Nguyên tắc kinh điển: "Code được đọc nhiều hơn được viết" — hãy viết code cho người khác (và chính bạn 6 tháng sau) dễ hiểu, không chỉ cho máy chạy được.
