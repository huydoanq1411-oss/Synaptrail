Cải thiện cấu trúc code nội bộ mà không thay đổi hành vi bên ngoài của chương trình.

Ví dụ: Extract Method (tách hàm)

refactor_extract_method.py 
# TRƯỚC - một hàm làm quá nhiều việc
def xu_ly_don_hang(don_hang):
    tong = sum(sp["gia"] * sp["so_luong"] for sp in don_hang["san_pham"])
    if don_hang["ma_giam_gia"]:
        tong = tong * 0.9
    print(f"Tổng: {tong}")
    # ... gửi email, lưu database, v.v.

# SAU - tách thành các hàm nhỏ, mỗi hàm một nhiệm vụ rõ ràng
def tinh_tong_tien(san_pham_list):
    return sum(sp["gia"] * sp["so_luong"] for sp in san_pham_list)

def ap_dung_giam_gia(tong, co_ma_giam_gia):
    return tong * 0.9 if co_ma_giam_gia else tong

def xu_ly_don_hang(don_hang):
    tong = tinh_tong_tien(don_hang["san_pham"])
    tong = ap_dung_giam_gia(tong, don_hang["ma_giam_gia"])
    print(f"Tổng: {tong}")
Quan trọng
Refactoring an toàn nhất khi có bộ test đầy đủ (chương 87-88) — chạy test trước và sau khi refactor để đảm bảo hành vi chương trình không bị thay đổi ngoài ý muốn.

Các dấu hiệu code "có mùi" (code smell) cần refactor

  • Hàm quá dài, làm quá nhiều việc.
  • Code trùng lặp ở nhiều nơi (nên tách thành hàm dùng chung).
  • Class có quá nhiều thuộc tính/phương thức không liên quan nhau.
  • Tên biến/hàm mơ hồ, không rõ nghĩa.
